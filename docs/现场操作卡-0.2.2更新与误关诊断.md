# 现场操作卡：0.2.2 自动更新验证 + 页面误关诊断

> 一次现场做两件事：先采集页面误关的证据，再在受控副本上验证 0.2.2 的自动更新与回滚。
> 全部在本机操作。除「造旧版本副本」这一步外，不改正式安装目录。
> 命令里的盘符和路径按现场实际替换。

## 一、去之前准备什么

### 1. 要带的文件

| 文件 | 从哪拿 | 放到现场哪里 |
|---|---|---|
| `classbeat-0.2.2.zip` 解压出的完整目录 | Release `v0.2.2` | 现场机器 `E:\ClassBeat`（正式安装） |
| `classbeat-0.2.2-single.html` | Release `v0.2.2` | U 盘（对照用，可选） |
| `update.json`、`classbeat-0.2.2.zip` | Release `v0.2.2` | `E:\更新源`（只在没有外网时用） |
| `tools\diag\detect.ps1` | 仓库 | U 盘 |
| `tools\launcher\` 里的 4 个脚本 | 仓库 | U 盘（现场要恢复自动拉起时用） |
| 现有安装目录的整份副本 | 现场机器 | U 盘或 `E:\现场备份\20261116` |

### 2. 先备份现有配置

先停服务，再整目录复制：

```powershell
Copy-Item -Recurse "E:\ClassBeat" "E:\现场备份\ClassBeat-20261116"
```

至少确认副本里包含 `data\`、`assets\`、`server\messages.json`。正式目录里的这三处，本次全程不删、不改。

要还原：先停服务，把备份目录整个拷回原位。

### 3. 还原卡

**先问清这台一体机有没有还原卡 / 冰点还原（待现场确认）。** 有的话，重启会把 C 盘恢复原样：

- 测试副本、备份、更新源都放非还原分区（如 `E:\`）或 U 盘；
- 本次更新结果在重启后可能消失，记录表里注明。

### 4. 选更新源（现场二选一）

**A. 有外网**：直接用 Release 上的清单，地址固定：

```text
https://github.com/sulengyin/ClassBeat/releases/download/v0.2.2/update.json
```

到现场先用浏览器打开这个地址，能看到 JSON 才算通。

**B. 没有外网**：本机架一个静态源。

1. 新建 `E:\更新源`，放入 `update.json` 和 `classbeat-0.2.2.zip`。
2. 用记事本打开 `update.json`，只改 `"url"` 一行：

   ```json
   "url": "http://127.0.0.1:9000/classbeat-0.2.2.zip",
   ```

   其它字段不动（`sha256`、`bytes` 都是这个 zip 的，改了 url 不影响）。
3. 另开一个窗口起静态服务：

   ```powershell
   cd /d E:\更新源
   py -3 -m http.server 9000
   ```

   没有系统 Python 时改用安装目录自带的：`E:\ClassBeat\server\python\python.exe -m http.server 9000`（自带运行时是否带 `http.server` 待现场确认）。
4. 这个窗口要一直开着。清单地址就是 `http://127.0.0.1:9000/update.json`。

### 5. 停掉自动拉起

现场测试期间，别让看门狗把页面又拉起来：按 `docs\使用-大屏自动恢复.md`「五、临时停掉自动恢复」在 `tools\launcher\` 放一个空文件 `stop.flag`。

## 二、现场第一步：先采集，再复现

**顺序不能反**：先采集基线，再让黑板蹭屏幕复现，最后再采集一次对比。

### 1. 采集（复现前）

方法一，右键 `detect.ps1` →「使用 PowerShell 运行」。输出只在窗口里，不留文件。

方法二，要留文件，在 PowerShell 里执行：

```powershell
New-Item -ItemType Directory -Force "E:\现场" | Out-Null
powershell -ExecutionPolicy Bypass -File "E:\ClassBeat\tools\diag\detect.ps1" | Tee-Object -FilePath "E:\现场\detect-复现前.txt"
```

脚本只读：不写注册表、不改设置、不装东西、不停服务。

### 2. 重点看这几段

| 段 | 看什么 |
|---|---|
| 1. 系统信息 | 有没有触摸设备 |
| 2. 平板模式 | `TabletMode` 是 1 还是 0 |
| 3. 边缘手势 | 有没有 `AllowEdgeSwipe`，值是多少 |
| 4. 浏览器进程 | 启动参数里有没有 `--kiosk` / `--app` |
| 5. 启动文件夹 | 有没有指向本地页面的快捷方式 |
| 6. 服务与端口 | 8765–8774、8805 上是谁在监听 |
| 结论提示（疑似） | 整段原样保留，别只摘一句 |

### 3. 复现并记录

按 `docs\诊断-页面被误触关闭.md` 第二节做一次，第三节的记录表填完。

### 4. 复现后再采集一次

```powershell
powershell -ExecutionPolicy Bypass -File "E:\ClassBeat\tools\diag\detect.ps1" | Tee-Object -FilePath "E:\现场\detect-复现后.txt"
```

把「复现前」「复现后」和记录表一起带回。

## 三、现场第二步：确认版本，必要时造一个旧版本

### 1. 正常启动，确认当前版本

1. 双击 `打开大屏.bat`。
2. 点右下角「⋯」展开工具条，**工具条最右端**显示版本，如 `v0.2.2 · 38e6e9b`。
3. 再核对一次接口：浏览器打开 `http://127.0.0.1:8765/version`，看 `version` 和 `build`。

把看到的版本号记进第七节记录表。端口被占时会顺延，以启动时窗口打印的端口为准。

### 2. 如果已经是 0.2.2

Release 的 `0.2.1` 包**不能**当升级起点：它的 `server\` 里只有 `phone.html`、`rhythm_server.py`、`run.py`，没有 `updater.py`，页面上也没有「版本与更新」面板。它只能验证「有新版本」提示条，点不了更新。

所以要造一个**受控旧版本**：

1. 先停正式服务（见第四节第 5 步的重启说明），腾出 8765。
2. 整目录复制一份：

   ```powershell
   Copy-Item -Recurse "E:\ClassBeat" "E:\ClassBeat-旧版"
   ```

3. 记事本打开 `E:\ClassBeat-旧版\app\version.js`，只改一行：

   ```js
   var VERSION = "0.2.1";
   ```

   `BUILD` 不动。
4. 双击 `E:\ClassBeat-旧版\打开大屏.bat`。
5. 展开「⋯」，确认显示 `v0.2.1 · 38e6e9b`。

记录表里写明：这是**受控旧版本**（0.2.2 的代码，只把版本号改成 0.2.1），不是 Release 的 0.2.1 包。正式目录没动。

## 四、现场第三步：带 `--update-url` 启动，点更新

### 1. 参数与启动方式（代码事实）

- 参数名是 `--update-url`，由 `server\rhythm_server.py` 解析；另有 `--update-interval`，默认 1800 秒。
- 也可以不传参数，改用环境变量 `CLASSBEAT_UPDATE_URL`。
- **`server\run.py` 不转发这个参数**：`打开大屏.bat` / `启动手机服务.bat` 双击启动时不带更新源。要带更新源，只能手工起 `rhythm_server.py`。

### 2. 停掉用 bat 起的副本服务

双击 `E:\ClassBeat-旧版\停止手机服务.bat`。它按 `server\service.pid` 结束进程树。

### 3. 前台启动

```powershell
cd /d E:\ClassBeat-旧版\server
python\python.exe rhythm_server.py --update-url "https://github.com/sulengyin/ClassBeat/releases/download/v0.2.2/update.json"
```

离线源就换成 `--update-url "http://127.0.0.1:9000/update.json"`。

- **这个窗口不能关**；结束时按 `Ctrl+C`。
- 窗口会打印「教室消息服务已启动」「手机打开 …」「大屏同源 …」「本机自测 …」。
- 8765 被占时会打印 `[!] 8765 被别的程序占了，已改用 8766`，后面一律用打印出来的端口。
- 手工这样启动**不会写 `service.pid`**，`停止手机服务.bat` 停不了它，只能用 `Ctrl+C`。

浏览器打开 `http://127.0.0.1:8765/screen`（端口顺延就换）。

### 4. 打开面板，逐步核对

入口有两个，内容一样：

- 大屏：点「⋯」→ 工具条里的「更新」；
- 设置页：点「⋯」→「配置班级」→ 一直「下一步」到最后一页 →「版本与更新」。

按顺序操作，对照屏幕：

| 步骤 | 屏幕上应看到 |
|---|---|
| 打开面板 | 标题「版本与更新」；「当前版本 v0.2.1 · 38e6e9b」。启动时的自动检查通常已经报过有新版，面板会自动补一次检查，直接显示「发现新版本 v0.2.2。」；没赶上自动检查则先显示「还没有检查更新。」，按钮「检查更新」 |
| 点「检查更新」（如已显示新版本可跳过） | 先显示「正在检查更新…」，约 1 秒后变成「发现新版本 v0.2.2。」；下方出现更新说明；按钮多出「立即更新」 |
| 点「立即更新」 | 先显示「正在更新，请稍等…」，随后出现进度条；文字依次为「正在下载 v0.2.2…」→「正在解压…」→「正在备份当前版本…」→「正在替换程序文件…」→「正在检查页面和版本号…」 |
| 完成 | 「已更新到 v0.2.2，重启后完全生效」；另有一行固定的「更新已完成，需要重启服务才完全生效。」；按钮剩「检查更新」「回滚到上一版」 |
| 核对备份 | `E:\ClassBeat-旧版\backups\program\` 下多出 `<日期时间>-v0.2.1\`，里面有 `meta.json` 和 `files\` |

面板开着时每 2 秒自动刷新，不用手点。更新期间不要连点按钮。

启动后屏幕底部也可能先出现一条「有新版本 v0.2.2 可用，请联系管理员更新。现在照常使用。」，点「知道了」关掉即可，不影响面板操作。

### 5. 重启服务，确认版本变化

1. 在启动窗口按 `Ctrl+C`，窗口出现「已停止」。
2. 再执行第四节第 3 步同一条命令。
3. 重新打开 `http://127.0.0.1:8765/screen`（页面必须重开或刷新，版本号只在页面启动时读一次）。
4. 展开「⋯」，应显示 `v0.2.2 · 38e6e9b`。
5. 浏览器打开 `http://127.0.0.1:8765/version`，`version` 应为 `0.2.2`。
6. 打开 `http://127.0.0.1:8765/api/update/status`，核对 `currentVersion` 为 `0.2.2`、`hasBackup` 为 `true`。

### 6. 更新状态与日志在哪看

| 位置 | 内容 |
|---|---|
| `GET /api/update/status` | 当前状态：`state`、`progress`、`message`、`error`、`currentVersion`、`latest`、`available`、`canApply`、`blockedReason`、`hasBackup`、`last` |
| `GET /api/update` | 版本、build、有没有新版；不返回更新源地址 |
| `GET /version` 或 `/api/version` | 版本、build、启动时间 |
| `backups\program\last.json` | 最近一次更新/回滚结果：`action`、`ok`、`fromVersion`、`toVersion`、`message`、`backup` |
| `backups\program\<日期时间>-v<版本>\meta.json` | 这份备份从哪个版本来、包含哪些文件及其哈希 |
| 启动窗口 / `server\server.log` | 用 bat（`run.py`）启动时，服务输出写 `server\server.log`；手工前台启动时只打在窗口里。更新线程的异常栈也在这里 |

更新模块本身不写独立日志文件，失败原因以 `/api/update/status` 的 `error` 和 `last.json` 为准。

## 五、现场第四步：验证回滚

### 1. 什么时候点「回滚到上一版」

- 更新完成并重启后，页面显示不对、版本号不对，或老师现场试用不能接受；
- 只是想演示「怎么退回上一版」。

更新过程中健康检查不过，程序会**自动**恢复备份，不需要人点。这种情况面板只显示一句失败原因，`last.json` 里 `action` 是 `update`、`ok` 是 `false`。

### 2. 操作与预期

| 步骤 | 屏幕上应看到 |
|---|---|
| 打开面板 | 「当前版本 v0.2.2 · 38e6e9b」；出现「回滚到上一版」按钮 |
| 点「回滚到上一版」 | 「正在回到 v0.2.1…」 |
| 完成 | 「已回到 v0.2.1，重启后完全生效」；同一行「更新已完成，需要重启服务才完全生效。」 |
| 重启后 | 「⋯」里显示 `v0.2.1 · 38e6e9b`；`/version` 的 `version` 为 `0.2.1` |

### 3. 核对

- `/api/update/status` 的 `currentVersion` 变回 `0.2.1`；
- `backups\program\last.json` 里 `action` 为 `rollback`、`ok` 为 `true`、`toVersion` 为 `0.2.1`。

回滚用的是最近一份备份，备份只保留两份。回滚后再更新，会重新备份当前版本。

## 六、出问题怎么判断

| 现象（面板/窗口上的一句话） | 先看哪里 | 怎么恢复 |
|---|---|---|
| 「连不上更新服务器，请检查网络后再试」 | `/api/update/status` 的 `error`；浏览器直接打开 `--update-url` 地址 | 打开能通就是包下载域被挡，换本地更新源；都不通就检查网络/静态服务窗口 |
| 「下载中断，请检查网络后重试」 | `last.json` 的 `message` | 重试；反复失败改用本地源 |
| 「下载失败（服务器返回 404）」 | `update.json` 的 `url` 是否指向本次 zip | 改成正确的 zip 地址后重试 |
| 「安装包大小不对…」「安装包 SHA256 校验失败…」 | 本地 zip 是否拷完整、是否被改过 | 重新拷 `classbeat-0.2.2.zip`；线上源则重试 |
| 「安装包里的 xxx 校验失败」 | `update.json` 与 zip 是否同一版 | 换成配套的一对，不要混用 |
| 「「xxx」被占用，重试后仍然换不了」 | 谁占着这个文件（编辑器、杀软、另一个服务） | 关掉占用程序后重试；失败会自动恢复原文件 |
| 端口不是 8765 | 启动窗口的 `[!] … 已改用 8766`；`detect.ps1` 第 6 段有 PID | 用打印出来的端口打开 `/screen`；或停掉占用程序 |
| 点了更新像没反应 | `/api/update/status` 的 `state` 与 `busy` | 面板每 2 秒自动刷新，别连点；`state=failed` 看 `error` |
| 重启后版本号还是旧的 | `http://127.0.0.1:8765/version` | 说明旧进程还占着 8765 或页面没刷新：彻底停服务→再启动→重开页面 |
| 更新后页面打不开 | `last.json`；`/api/update/status` | 健康检查会自动恢复；确认 `/screen` 能打开 |
| 看不到「回滚到上一版」 | `status.hasBackup` | 为 `false` 就是没有可回滚的备份（没更新过，或备份已被清理） |
| 服务起不来、窗口一闪就没 | `server\server.log`；手工前台启动时的报错 | 检查 `server\python\` 是否完整，端口是否全被占 |
