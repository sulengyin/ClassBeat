## 一、安装与冷启动就绪（阶段 4 最优先）

1. 有还原卡？**先问网管/IT**，结果记进记录表。有还原就把包放非还原分区。
2. 安装 `classbeat-0.3.1.zip`，双击「安装开机自启.bat」。
3. **关机再开机**，从按下电源开始计时，记录：
   - [ ] 开机到登录桌面耗时
   - [ ] 大屏页面自动出现耗时（目标 ≤30 秒）
   - [ ] 是否需要任何人工点击（目标：零干预）
4. 重复开关机 2 次，确认每天都这样。

## 二、看门狗 / 逃生门全流程（9.6 缓解措施 1+2）

按 `docs/使用-大屏自动恢复.md` 的步骤，逐项验证并勾选：

- [ ] 双击「大屏全屏.bat」：kiosk 打开，无地址栏/标签页；重复双击不开第二个窗口
- [ ] 误关页面（或用任务管理器结束浏览器）：看门狗几秒内自动拉起
- [ ] 一分钟内连续触发 4 次：第 4 次不再拉（防反复弹窗）
- [ ] 锁屏 / 注销时看门狗不抢
- [ ] 「退出大屏.bat」：看门狗先停手 → 窗口关闭 → 回到桌面，不会「关了又被拉回来」
- [ ] 再双击「大屏全屏.bat」能回大屏

## 三、误关复现诊断（9.6，只观察不改设置）

如果当天黑板一拉就复现，按《诊断-页面被误触关闭.md》做：
1. 先跑只读检测 `tools/diag/detect.ps1`，输出全部复制带走。
2. 填那张 10 行记录表（任务栏/桌面/手势动画/鼠标对照）。
3. 若当天不复现，也记录「今天未复现」，证据要靠后续教学日累积。

## 四、单日 8 小时内存曲线（阶段 4 长跑・单日部分）

用当天剩余的在校时间挂机。把 `tools/diag/mem-curve.ps1` 拷到现场，
在 PowerShell 里跑（路径换成现场实际）：

```powershell
powershell -ExecutionPolicy Bypass -File .\mem-curve.ps1 `
    -OutputPath "E:\验收记录\内存曲线-20261119.csv"
```

每分钟采一次 chrome/msedge/python 进程内存，Ctrl+C 停止。

- [ ] 记录文件在离开教室前拷回 U 盘
- [ ] 顺带记录：期间页面是否白屏/卡顿、消息是否还能收

## 六、钉钉体验应用入口实验（P3 第一步，新增待核实项）

> **2026-11-17 本机实验已发现一个问题**：钉钉里第一次打开正常，再点只剩白屏。
> 排查已排除 HTTP 缓存与 SW 拦截（见 PLAN 2.37），phone.html 已加 pageshow/回前台探活兜底；
> 但若钉钉杀掉渲染进程后 JS 不执行，客户端兜底无效。当天带着下面的取证清单做。

1. 提前在钉钉工作台「创建应用 → 将链接添加为应用」填好：
   - 名称：班级节律屏 · 班名
   - 移动端链接：`http://<教室电脑IP>:8765`
   - PC 端链接：`http://<教室电脑IP>:8765/screen`
   - 授权范围：**仅自己（不要选全部员工）**
2. 在手机钉钉里点这个应用图标，记录：
   - [ ] 首次打开是否正常
   - [ ] **二次点击是否白屏（11-17 已复现）**；白屏时依次试：下拉刷新 → 杀掉钉钉重开 → 清该应用缓存，记下哪一步能救回来
   - [ ] 若被拦/报错：提示文字是什么（截图）
   - [ ] 能打开的话：发消息、改设置是否与系统浏览器一致
3. 对照实验：把同一链接发到钉钉聊天里，点聊天里的链接再试一次。
4. 结论只记录事实，不当场改方案。
