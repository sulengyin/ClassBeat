# 诊断：大屏页面被移动黑板误触关闭

> 适用现象：拉动移动黑板时蹭到大屏，**这个页面 / 窗口被关掉了，但大屏本身还是开机的**（不是断电、不是休眠、不是信号线问题）。
> 本文是给老师和现场使用者的操作卡，不需要懂代码，照着做即可。全程只观察、只记录，不修改任何系统设置。

## 一、先做一件事：跑一次只读检测

仓库里有一个只读检测脚本：`tools/diag/detect.ps1`。

**它做什么**：只读取系统信息、平板模式、边缘手势设置、浏览器启动方式、启动项、端口和近期事件，然后打印出来。
**它不做什么**：不写注册表、不改任何设置、不安装任何软件、不停止任何服务。

运行方法（二选一）：

1. 右键 `detect.ps1` →「使用 PowerShell 运行」。
2. 如果提示「无法加载文件，因为在此系统上禁止运行脚本」，打开 PowerShell，执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File "<detect.ps1 的完整路径>"
   ```

   （`-ExecutionPolicy Bypass` 只对这一次运行生效，不会永久修改系统策略。）

拿到输出后，把整段文字复制回来即可；脚本最后有「未能检测的项」和「结论提示（疑似）」，也一起复制。

## 二、现场复现与记录

请在教室那台一体机上，按下面的顺序试一次，边试边记录。

### 第 1 步：确认被关掉的是什么

黑板蹭过之后，先看三样东西：

- 屏幕底部任务栏还在不在？
- 是退回了 Windows 桌面，还是只是这个页面退出了全屏？
- 大屏的电源指示灯是否仍然亮着（确认机器没关机）？

### 第 2 步：确认规律

- 是**每次**拉动黑板都发生，还是偶尔发生？
- 只发生在**某个位置**（比如黑板推到屏幕左侧 / 右侧末端）吗？
- 只发生在**某个方向**（比如往里推、往外拉）吗？

### 第 3 步：看关闭瞬间的画面

被关掉的那一下，屏幕上有没有出现：

- 从屏幕边缘滑出的动画（像把手势拖下去）；
- 窗口缩小 / 最小化的动画；
- 还是「啪」一下就没了，没有任何动画。

### 第 4 步：鼠标对照

把黑板移开，页面重新打开后：

- 用鼠标去点浏览器右上角的关闭按钮，能不能关掉？
- 如果能，说明「点到按钮」这条路径是通的；
- 如果窗口是全屏、根本没有可见的关闭按钮，那更可能是手势。

## 四、把结果发回

1. 把检测脚本的**全部输出**复制粘贴回来（从「ClassBeat 只读诊断」到最后的「本脚本只读，未修改任何设置。」）。

3. 如果方便，拍一张关闭瞬间的屏幕照片或几秒短视频，能帮助判断有没有手势动画。

## 五、几个注意点

- 检测脚本**只读**，不会改设置，也不会把任何数据发到网上。
- 不要为了「试试看」去修改系统的手势或电源设置，现场先保持原样，否则后面无法判断原因。
- 如果页面被关掉后手机仍能收到大屏通知，说明后台服务还活着，被关掉的只是显示页面——这是重要线索，请一并记录。
- 本卡只用于收集证据，不代表已经定位原因；结论要等现场复现和脚本输出一起看。
