### 2.2 午间不是一个"午休"块，而是一个内容可变的槽位（CONFIRMED）

用户确认：**午休时间是 12:10–12:50**，但同一学期里这段内容会变——有时必须午睡，有时必须大扫除，有时自主写作业。并且明确要求：**时间范围和提醒文字都要能自己改。**

这条把作息表从"20 个固定块"重新理解为"锚点 + 槽位"：

| 类别 | 成员 | 谁有权改 | 变化频率 |
|---|---|---|---|
| 锚点 | 7 节课、2 次眼保健操、2 次大课间、2 段课后服务 | 教务处 | 一学期基本不变 |
| 固定槽位 | 午餐 11:40–12:10（ASSUMED，由 12:10 起点反推） | 教务处 | 很稳定 |
| 可变槽位 | 午间 12:10–12:50 | 班主任 | 可以天天不同 |
| 空白槽位 | 6 段课间 | 无内容 | 自由活动，只提示下节课 |

区别不在时长，而在**谁有权改**。锚点只有学校能改，槽位必须允许班主任现场改，而且改的是配置不是代码。

推论：状态机不能把午间写成 `type:"meal", name:"午休"` 这种常量，必须做成
`slot(kind=noon, start, end, title, tip, items[])`，渲染只负责把字段放上屏。

### 2.3 午间有四个来源，必须定优先级（CONFIRMED）

用户确认了三件事，合起来改变了午间的性质：

- **大扫除**：一般规定固定周几
- **自主作业**：由**当天中午看护该班的老师**决定
- **全校统一午休**：看学校什么时候通知

同一段 12:10–12:50，可能有四种来源同时成立。必须定死优先级：

| 优先级 | 来源 | 谁写 | 典型 |
|---|---|---|---|
| 1（最高） | 学校统一通知 | 教务处 | 今天全校统一午休 |
| 2 | 当天临时调整 | 中午看护老师 / 班主任 | 今天改自主作业 |
| 3 | 周几固定安排 | 班主任，一次设定 | 每周三大扫除 |
| 4（兜底） | 默认模板 | 系统 | 午间休息 |

三条产品含义：

1. **午间不是班主任一个人的事**。看护老师也是操作者，所以编辑权必须按「角色 × 时段」切分，不能只挂一个全局验证码。验证码防误触，防不了越权。
2. ~~屏幕必须显示这条安排从哪来~~ → **来源只给老师看，不给学生看**。「学校统一通知」「今天临时调整」都是系统语言，学生看不懂也不需要。这是我在第五轮写错的一条，见 2.4。
3. **「今天谁看班」必须上屏**。学生不知道听谁的，才是真实的管理成本，而不是技术问题。

### 2.4 通知不是内容，是事件（CONFIRMED，用户纠正）

用户明确指出：**学校里的通知面向教师，不直接面向学生，中间必须由教师做一次语言转化。**

| 层 | 内容 | 读者 | 例子 |
|---|---|---|---|
| 通知原文 | 全校统一午休，请各班做好午休管理 | 教师 | 行政语言，**不可直接展示** |
| 班级指令 | 今天中午全校安静午睡 | 教师确认后 | 半转化 |
| 大屏文案 | 闭眼趴一会儿，不讲话 | 学生 | 可执行语言 |

三条产品含义：

1. **系统不能"一键转发"**。任何来自外部的文字，上屏前必须经过教师确认，系统只提供改写入口和默认草稿。
2. **系统的价值不是替老师决定说什么，而是记住他上次怎么说**。第一次手写，第二次给候选。这是内容包的第三层——**场景话术库**（另两层是科目准备清单、安全提示库）。
3. **大屏是"学生语言区"**。系统状态、行政术语、来源标注一律不得出现在这里。这一条同时否掉了第五轮"在学校通知上标来源"的做法。

推论：P4 的"手机发到大屏"也必须经过这一步。老师在外面发的消息，同样要区分「发给老师看的」和「发给学生看的」两种输入形态，否则就是把行政语言直接推到小学生面前。

### 2.5 通知到屏幕，中间不是"改写"，是"查惯例"（CONFIRMED，真实样本）

用户提供了真实样本。把通知原文和老师实际说的话放在一起，问题就清楚了。

> 通知：亲们，午间活动务必动起来哈[捧脸][捧脸]晚点校长室会抽查。
>
> 老师说的：今天中午 12:50 开始大扫除，先打扫自己的座位 + 一些提醒事项。

| 要素 | 通知原文有吗 | 老师补的 |
|---|---|---|
| 做什么 | 无，只有"动起来" | 大扫除 |
| 几点开始 | 无 | 12:50 |
| 先做什么 | 无 | 打扫自己的座位 |
| 注意什么 | 无，只有"抽查" | 提醒事项 |
| 为什么做 | 校长室抽查 | **刻意不告诉学生** |

四条结论：

1. **"从原文提取"这条路走不通**。原文没有可提取的内容，只有行政黑话和压力。任何宣称"AI 自动理解学校通知"的方案，在这个样本上都会编造。
2. **系统能做的是匹配惯例，不是改写文本**。它该知道"午间活动检查"在本班对应"周三大扫除、12:50 开始、先扫自己座位"，然后只问一句"今天还是这样吗"。
3. **转化包含"删掉"**。"校长室会抽查"是对老师的压力，不该传给学生。如果系统做摘要，很容易把这句话留下来——那是最坏的结果。
4. **这套映射是每个班独有的**。换个学校，"动起来"可能是跑操、可能是整理书包。这是内容包里最难被抄走的一层。

产品推论：通知入口的正确形态是**一个只有一行输入的确认框**，不是聊天窗口。

### 2.6 时间必须核对，不能推断（CONFIRMED，含一次真实纠错）

用户口述"12:50 开始大扫除"，我据此设计了"午间末尾动作"。**实际是 11:50**，大扫除在午间**之前**：

| 时段 | 内容 | 说明 |
|---|---|---|
| 11:40–11:50 | 午餐 | 大扫除日被压缩 |
| 11:50–12:10 | 大扫除 | 20 分钟，扫完进午休 |
| 12:10–12:50 | 午间休息 / 自主作业 | 原定槽位 |

这是本项目第二次在时间上出错：

| # | 错在哪 | 实际 |
|---|---|---|
| 1 | 课表第 4 节印 11:20–11:30 | 11:20–11:40（课表笔误） |
| 2 | 大扫除口述 12:50 | 11:50 |

两次都不是理解错，是**没有核对**。所以定一条规矩：

> **任何时间点在进入模型前，必须与作息表或用户逐字回读一遍。口述时间一律复述确认后再落库。**

这条比任何架构原则都实用。作息是这类产品的底座，底座错 10 分钟，整天的提示全错。

### 2.7 大扫除不是"午间内容"，是"午间前的插入动作"（CONFIRMED）

这条改变了槽位模型：

- 午间槽位（12:10–12:50）描述"这段时间做什么"
- 大扫除是**插在午餐与午间之间的独立动作**（11:50–12:10），有自己的时长、任务清单和结束倒计时
- 两者是**串联**，不是替换

所以槽位要支持 `pre`（前置动作）——一个有时长、有任务、能单独倒计时的块。原来的"把整个午间换成大扫除"是错的。

**补充（已确认）**：午餐时间不固定，一般 12:00 前后吃完；**目前中午 12:10 打铃**，但这个时间本身也会变，用户明确要求"这块的时间让用户自己设置"。

### 2.8 午间是一条"可配时间带"，不是三个写死的块（CONFIRMED）

```
11:40 ──[A 午餐结束]──[B 打铃]──13:00
  午餐       动作（可选）      午间
```

| 分界 | 含义 | 默认 | 谁定 |
|---|---|---|---|
| 11:40 | 第四节下课 | 锚点 | 学校 |
| A | 午餐结束 / 动作开始 | 11:50 | 班主任 |
| B | 打铃，午间开始 | 12:10 | 班主任（会变） |
| 13:00 | 下午第一节 | 锚点 | 学校 |

没有动作的日子，午餐直接到 B。

原型已按此实现：改这三个时间，午餐、动作、午间三块自动重排，不会出现 0 分钟块或首尾交叉。这同时否掉了我之前把"11:40–12:10 午餐"写死的做法——**这类会变的作息必须建模成参数，否则每学期都要改一次代码。**

### 2.9 值日不是"一张表"，是两套并行的岗位体系（CONFIRMED，真实材料）

用户给的两张表，结构完全不同：

| | 小岗位表 | 值日组表 |
|---|---|---|
| 换人方式 | 一人一岗，学期内基本不动 | A/B 两组按**日期区间**轮换（9/4–9/11、9/28–10/16） |
| 岗位名 | 老师自造：外墙美丽师、讲台清理师、绿植守护者 | 通用名：扫地、倒垃圾、包干区 |
| 一行几人 | 1–8 人不等 | 每组 1–4 人 |
| 频率 | 每节课 / 每天 N 次 / 每周固定日 / 按事件 | 每天放学，组内分工 |
| 表头 | 岗位 / 负责人 / 职责 | 项目 / A组 / B组 / 打扫时间 |

**所以系统里不该有"值日表"这个对象，只该有"岗位"这个对象，每个岗位自带时间规则和换人方式。**所谓"值日表"只是这些岗位的一个视图。

这条和 2.3 的"午间槽位"是同一个道理：不要按老师手里的纸来建模，要按纸背后的事实来建模。

### 2.10 频率是岗位的属性，不是排班的属性（CONFIRMED）

用户原话：擦讲台要每节课都打扫，倒垃圾只要早晨、中午、放学三次。

18 个岗位归成 5 类，外加一类"表上没写"：

| 类型 | 例子 | 触发方式 | 屏上表现 |
|---|---|---|---|
| 每节课 | 讲台清理师、多媒体管理员 | 每个课块结束 | 只在课间最后 2 分钟 |
| 每天 N 次 | 倒垃圾（早/中/放学）、体温（早/中） | 时点列表 | 到点出现 16 分钟 |
| 每周固定日 | 擦窗户（周二大扫除） | 周几 + 时点 | 当天到点 |
| 按事件 | 节能小队长（离开教室）、路队长（列队） | 事件名 | 事件发生 |
| 周期轮换 | 扫地、后柜窗台、包干区（A/B 组） | 日期区间 + 时点 | 到点，取当前组 |
| **未写** | 绿植守护者、连廊管理、外墙美丽师 | 无 | **不上屏** |

**红线：表上没写频率的岗位，系统不能默认为"每天"。** 猜错一次，学生就白跑一趟；而且错得没有报错，只有学生在教室里转圈。

### 2.11 "1 后面跟人名"是老师的私有编码，不能解析（CONFIRMED，用户强调）

黑板清洁师一栏写的是：`1 沈亦然 / 2 孔子墨 / 3 曹嘉禾 / 4 郑思远 / 5 华青禾 / 6 陈静姝`。

用户明确说：**这不是每个老师的规则，不能乱套用。**

| 能做 | 不能做 |
|---|---|
| 存显式的 `weekday → 人` 映射 | 内置"数字开头 = 周几"的解析规则 |
| 导入时识别为"疑似周几映射"，请老师确认一次 | 猜完直接生效 |
| 确认后写进数据，渲染时按当天取人 | 把 `1=周一` 写进代码 |

同一条原则在 2.4 已经出现过：**凡是靠猜的，都要老师确认一次。** 通知是这样，符号编码也是这样。

**已确认（2026-11-05）**：本班黑板的 `1–6` 里，**1–5 对应周一到周五，6 号陈静姝是替补**，特殊情况来帮忙。所以存成 `peopleMap{1-5}` + `substitute[陈静姝]`。

要注意的是：**"确认过"和"变成通用规则"是两件事**。这套映射只对五（1）班有效，绝不写成代码里的解析逻辑；换个班、换张表，仍然要重新问一遍。

### 2.12 名字像的岗位，频率可能差 7 倍（CONFIRMED）

"讲台清理师"每节课一次，"黑板清洁师"每天一次。两个名字都带"清洁/清理"，都是"XX师"，频率差 7 倍。

所以**不能按岗位名推断频率**，频率必须是独立字段。任何"智能识别岗位类型"的设计在这里都会出错。

### 2.13 放学是"并发 + 有序"，不是一串独立提醒（CONFIRMED）

17:10 同时满足条件的有 6 件事（周二大扫除日再加擦窗户，共 7 件）：

```
倒垃圾 · 扫地 · 后柜窗台 · 包干区 · 关电关窗 · 排队下楼
```

这 6 件不是并列的：

1. 前 4 件都归"值日组"，可以合成一步
2. 关电关窗必须在人走之后
3. 排队必须最后

所以屏上压成 3 步：**值日组（4 项）→ 节能小队长 → 路队长**。

推论：岗位需要 `order` 字段，而且这个顺序是**班主任定的**，不是系统推的。系统推不出"我们班习惯先扫地再关窗"。

### 2.14 每节课的岗位常驻，但必须降权（CONFIRMED，用户决定）

每节课后有 2 个岗位触发。原型里做了两个约束去量化它：

- 一次课间挂两个岗位（讲台清理师、多媒体管理员）
- 只在课间出现，午休、午餐、课后服务不挂

实测：一天约 108 分钟屏上有值日条（6 段课间 65 分钟 + 早到校/放学/午餐 43 分钟），占在校时间 **20%**（5 天 2705 分钟里 541 分钟）。如果放宽到"从下课一直挂到下次下课"，会到 31%；如果全天常驻，会到 51%——那时它彻底变成背景。

用户的决定是：**一直显示，学生自己看。**

这个判断成立，但前提是**视觉上必须降权**，否则它就变成第二个"注意安全"标语。所以实现上分两层：

| 层 | 内容 | 样式 |
|---|---|---|
| 日常岗位 | 讲台清理师、多媒体管理员 | 灰字、无底色、字号小一档 |
| 此刻值日 | 值日组、放学、早到校 | 橙色、第一条加粗 |

并且定一条让位规则：**只要有临时任务，日常岗位就不显示。** 也就是说"讲台清理师"永远不会和"值日组 4 项"抢同一行。

这样 31% 的屏时是存在的，但它占的是"没有别的事要说"的那 31%，而不是覆盖真正需要学生行动的时刻。

### 2.14b 擦窗户不是独立岗位，是"大扫除"的子任务（CONFIRMED，用户确认）

用户确认：**擦窗户的"每周二"，就是周二午间那场大扫除。**

这改变了它的类型：它不该有自己的时间规则，而是挂在"大扫除"这个动作上，跟着 11:50–12:10 走。

| | 独立岗位 | 附属任务 |
|---|---|---|
| 时间来源 | 自己的 freq | 宿主动作的时间 |
| 例子 | 倒垃圾（早/中/晚） | 擦窗户（周二的 11:50–12:10） |
| 换天 | 按自己的规则 | 那天没做大扫除，它就不出现 |

顺带修正了一处：原型之前把大扫除默认设在周三，是我自己假设的。表上写的就是周二，已改。

### 2.15 表上有两处人手改过，说明表会腐烂（CONFIRMED）

1. 后柜窗台：吴亦然被划掉，手写"赵予安（替补）"
2. 底部手写：**扫地的同学自主协调，自己商量扫哪一大组，以及教室最前+最后谁负责**

第二条最要紧。它说明：

> **有些岗位不需要系统派单，只需要系统"召集"。**

系统把"扫地组 4 人"叫出来就够了，谁扫哪组让他们自己商量。老师本来就故意留了这个协商空间——因为每天的情况不一样（地上脏的地方不一样）。

这否定了一种常见做法：把任务分配到每个人、每个格子。在小学里，过度分配反而是负担。

数据模型要能表达：`assign: fixed | self-organize`。

**而且手写修改本身是常态。** 系统如果要求"改一次就得重填整张表"，老师会放弃。必须支持单条改动 + 替补，且替补要能标"临时/长期"。

### 2.16 值日表告诉你"谁做什么"，但不告诉你"几点做"（CONFIRMED，重要）

把 18 个岗位的时间栏摊开看：

| 岗位 | 表上写的 | 能不能直接用 |
|---|---|---|
| 劳动委员 | **7:50** 检查班级卫生 | ✅ 唯一一个写了具体时间的 |
| 倒垃圾 | 早、中、放学三次 | 🔶 用户口述，时点要定 |
| 黑板清洁师 | 每天擦 | ❌ 几点擦没说 |
| 讲台清理师 | 整理讲台 | ❌ 频率都没写 |
| 班牌 | 每天早上 | 🔶 早上几点 |
| 体温管理员 | 早、中 | ❌ 中是哪一刻 |
| 补给站队长 | 领水果或奶类 | ❌ 饭前还是饭后 |
| 节能小队长 | 大家都离开教室的时候 | ❌ 事件，不是时间 |
| 扫地 / 后柜 / 包干区 | 打扫时间只写了日期区间 | ❌ 一天里几点没写 |
| 绿植 / 连廊 / 外墙 | 无 | ❌ 完全没写 |

**18 个岗位里，只有劳动委员写了具体时刻。**

这不是老师偷懒，而是这类表本来就是"责任分工表"，不是"时间表"。老师心里有时间，纸面上不需要。

## 这条推论比它看起来严重

如果要让 18 个岗位都上屏，老师就得填 18 次时间——这就是这类产品最常见的死法：**初始化成本高于收益，第一周就放弃。**

所以产品上必须把"填 18 次"降到"点 4 下"。可行的做法是提供**时段模板**：

| 模板 | 覆盖 | 班级里的实际岗位 |
|---|---|---|
| 早上到校（7:40–8:00） | 进了教室就做 | 班牌、作业管理、劳动委员、体温（早） |
| 每节课后 | 下课就做 | 讲台清理师、多媒体管理员、黑板清洁师 |
| 午餐后 | 吃完就做 | 补给站队长、体温（中）、倒垃圾（中） |
| 放学前 | 收拾完再走 | 倒垃圾、扫地、后柜、包干区、节能、路队长 |
| 每周固定日 | 大扫除那天 | 擦窗户 |
| 事件触发 | 发生才做 | 节能（离开教室）、路队长（列队） |

按这张表分，18 个岗位里有 15 个能落进前 4 个模板，只有 3 个需要单独设。

**这条决定了 P3 编辑面板长什么样**：不是一张 18 行的表格让你逐行填，而是"先把岗位拖进 4 个时段"，再逐个微调。

### 2.17 提醒内容让老师写，但要把"写"的成本降到最低（CONFIRMED，用户提议）

用户提出两条增强：**提前录入学生名单，输入时自动跳名字**；**记住这次内容，下次直接复用**。

这两条看起来是"输入法优化"和"便利功能"，实际上是同一件事的两半：

| 老师真正卡住的地方 | 表现 | 对应功能 |
|---|---|---|
| 想不起准确姓名 / 打错字 | "那个谁"、"赵予安"打成"杨震" | 名单补全 |
| 想不起上次怎么说的 | 每天把同一句午间提醒重打一遍 | 话术复用 |

在 65 寸触摸屏上用软键盘打 20 个汉字，大约 1–2 分钟。一天改三次就是 5 分钟。**真正让人放弃的不是这 5 分钟，是每次都要重新组织措辞。**

#### 名单不只是补全，它有三个用途

1. **输入补全**：打字时弹出候选
2. **岗位人员池**：换人、替补从这里选，而不是手打（2.15 的"单条改人"必须有人员池，否则改一次还是要打字）
3. **导入核对**：值日表导入时，表上有、名单里没有的名字 → 提示"这是转学生还是打错了"，而不是静默建一条脏数据

第 2 条决定了名单不能做成"输入辅助"这种可选小功能——**P3 的换人流程依赖它**。

#### 名单字段要克制

五（1）班实有 **48 人**（已收到名册，见 `data/students.json`），不需要学号、不需要性别、不需要家长电话。最小集：

```
Student   id, name, alias?, active, note?
```

| 字段 | 用途 | 说明 |
|---|---|---|
| `name` | 主键语义 | 中文姓名 |
| `alias` | 同名区分 | "郑思远 A"，只在名单内部显示，上屏仍用 `name` |
| `active` | 转走/休学 | **只能停用，不能删除** |
| `note` | 座位、组别 | 选填，老师爱填不填 |

红线：**名单里的人不可物理删除**。历史话术、替补记录、岗位表都引用着 `name`，删掉一个人会让半年前的记录变成空白。转走就 `active:false`，候选里不再出现，历史记录照常显示。

#### 名单从哪来：交付时预置，不在应用里做文件解析

老师手上是班级名册（Excel / Word / 一段文字）。**首版不做导入器**：

| 做法 | 采用 | 理由 |
|---|---|---|
| 老师把名单发给制作者，交付时预置 `students.json` | ✅ | 单班定制工具，一次性成本最低，无需在网页里塞 Excel/Word 解析库 |
| 应用内粘贴一段文本，按换行/逗号拆分 | ✅ 作为后续补录 | 转学生、漏录几个人时用，零依赖 |
| 应用内读 `.xlsx` / `.docx` | ❌ | 要引入 SheetJS / mammoth，破坏"零构建、单文件、可拷走"（第七节） |

首次建库是两条来源合并：**值日表里出现过的姓名去重先落一版**（实测 33 人），**再用老师给的名册补齐**（剩下 15 人）。两处对不上的名字列出来让老师点一次（同 2.15 的替补核对），不静默新增。

#### 真实名册的第一次检验：抓出 4 个错字（CONFIRMED）

拿 48 人名册去核对岗位表里的姓名，**4 处是转录错的**（已按名册修正原型）：

| 岗位表原写 | 名册 | 出现在 |
|---|---|---|
| 何沐源 | 周予宁 | 绿植守护者、擦窗户 |
| 李宇宸 | 卫浩然 | 扫地 A 组 |
| 钱语珊 | 何白露 | 扫地 B 组 |
| 许宴运 | 姜一诺 | 倒垃圾 A 组 |

33 个姓名错 4 个，**错字率 12%**。四个都是形近或音近的手误，而且系统不会报错——只会在屏上出现一个不存在的孩子，或者把任务派给查无此人。

这不是转录不认真，是**从图片/手写表抄名字的固有损耗**。所以名单的第一价值不是补全，是**校验基准**：凡是外部导入的姓名，都拿它比一次。

另外两条来自真实数据的约束：

- 48 人里 **33 人有岗位、15 人没有**。补全候选必须覆盖全部 48 人（点名用），不能只导入值日的人。
- 全班只有一对姓名编辑距离为 1：**周予安 / 周予宁**。输入"何沐"必须同时出两个，只能靠第三个字区分。**候选必须显示全名**，只显示后两字会直接选错。

#### 补全在触摸屏上怎么做（已确认：经常点名，按核心功能做）

用户确认**平时的提醒里会点到具体学生**，所以这不是附属功能，候选必须做重：

| 要求 | 做法 |
|---|---|
| 触发 | 输入第 1 个字就出候选，最多 5 条，不等到第 2 个字 |
| 排序 | 本场景岗位相关人 → 本场景最近点过的人 → 全名单最近使用 → 名单顺序 |
| 插入 | 点一下即插入，光标停在名字后面，不弹二级面板 |
| 键盘 | 上下键选择、回车插入（办公室电脑改内容时用得上） |
| 重名 | 同名时候选带 `alias`（"郑思远 A / B"），插入仍只写 `name` |
| 关闭 | 一键关闭补全，且记住"这个场景不用补全" |

"本场景岗位相关人"是这里唯一需要动脑的地方，也是最值钱的地方：编辑"擦黑板"时先跳黑板清洁师那 6 个人，而不是全班 40 人。这条不需要 AI，只需要把 `Role.people` 和当前编辑上下文对上。

#### 点名上屏的分寸（经常点名带来的新问题）

既然会经常写人名，就必须区分两种点名：

| 类型 | 例子 | 上屏 |
|---|---|---|
| 派任务 / 表扬 | 沈亦然，黑板交给你了 | ✅ 写人名 |
| 提醒没做 | 沈亦然，黑板又忘了 | ⚠️ **写事不写人**："黑板还没擦"，人名留在老师端 |
| 批评 / 比较 | 就你没交作业 | ❌ 不上屏，系统也不提供这个入口 |

理由不是"保护隐私"这种抽象说法，而是：65 寸屏挂在教室前面，被点名的孩子要在这个教室里待一整天。**系统的默认行为不应该制造这种后果。**

技术上不拦截，但提供两个默认：批评类模板出厂不预置；含"没 / 又 / 怎么"这类词的句子保存时提示一次"要不要只写事、不写人"。

#### 一个必须提前解决的冲突：大屏是全班可见的

老师输入"沈亦然 你又忘擦黑板"时，如果这行字实时出现在 65 寸屏上，等于当众点名。名单候选弹出来，也等于公开老师正在打谁的名字。

所以定一条：**任何进入编辑的动作，先把大屏切到遮挡页。**

| 状态 | 大屏显示 |
|---|---|
| 正常 | 五张卡 + 值日条 |
| 编辑中 | 遮挡页：班级名 + 当前时间 + "老师正在设置"，**不显示任何输入内容** |
| 退出编辑 | 3 秒后恢复，恢复时按当前时刻重新计算，不回到编辑前的画面 |

遮挡页不能是黑屏（学生会以为设备坏了、去按电源），也不能是静止图片（看起来像死机）。带秒针走动的时间是最低成本的"活着"的证据。

#### 话术复用：内容必须绑场景

如果历史记录是一个全局列表，一学期后就是 200 条的垃圾抽屉，老师翻两页就再也不打开。

| 场景键 | 例子 | 召回时机 |
|---|---|---|
| `noon:clean` | 周二大扫除怎么讲 | 打开"午间·大扫除"编辑 |
| `noon:notice` | 学校通知转化后的班级版本 | 收到同类通知时（2.5 的惯例匹配） |
| `break:calligraphy` | 书法课前准备提醒 | 书法课前一个课间 |
| `dismiss:weekday` | 放学三步走怎么说 | 放学前的编辑入口 |
| `free` | 任意自由提示 | 手动新增提示时 |

场景键不是让老师填的，是从"他点开了哪个编辑入口"自动带出来的。老师只感知到一件事：**在哪儿编辑，就弹出跟这儿有关的话。**

#### 记忆分两层，老师只操作第二层

| 层 | 谁决定 | 容量 | 屏上表现 |
|---|---|---|---|
| 最近 | 系统自动 | 每场景 5 条，滚动淘汰 | 灰字、折叠，默认不展开 |
| 记住 | **老师勾选** | 每场景 12 条，满了要求老师删 | 置顶、可命名 |

用户说的"选择是否记住"就是第二层。两层必须分开，原因有二：

1. **自动全记 = 必然膨胀**。老师一学期在午间场景写 60 次，全留下就是 60 条，等于没记。
2. **显式收藏才有信任感**。如果系统偷偷记下每一次，包括打错字的、骂人的、写了一半放弃的，老师会觉得这个屏幕不可控。

未勾选的内容也要留 5 条——因为"刚才那条改一下"是真实高频需求，比"翻出三个月前的模板"高得多。

#### 复用不是原样贴回

历史话术里最会过期的部分是时间词。"今天中午 12:50 大扫除"这句话，下周二复用就错了。

按 2.6 定下的规矩（时间必须核对，不能推断），复用后的处理是：

1. 点选历史条目 → 填入编辑框，**不直接生效**
2. 系统标出可能过期的片段：`今天 / 明天 / 周X / 具体时刻`
3. 保存前要求老师点一次确认，或手动改掉

**不做自动替换**。系统不知道"下周二大扫除几点开始"——那是配置里的事，而且 12:10 打铃这个时间本身还会变（2.8）。自动替换看起来聪明，实际是替老师做了一个他没同意的决定。

顺带说明：这条原则在本文档里已经出现第 4 次了（通知转化 2.4、数字编码 2.11、替补 2.13、过期时间词）。四次都指向同一件事：

> **系统可以准备好答案，但不能替老师按下确认。**

#### 与"内容包"的边界

2.4 提到内容包第三层是"场景话术库"，2.17 就是它的落地。但要分成两半：

| | 内置话术 | 班级话术（Phrase） |
|---|---|---|
| 来源 | 随版本发布，系统给的默认候选 | 老师自己写的 |
| 存储 | 代码/数据文件内 | 本地 `localStorage` |
| 升级时 | 可被新版覆盖 | **永不被覆盖、永不上传** |
| 删除 | 老师可隐藏 | 老师可删 |

红线：**版本升级不能覆盖老师写过的话。** 这是这类工具最容易失去信任的一刻——老师花一学期攒下的措辞，一次更新全没了，就再也不会写第二次。

#### 数据结构

```
Student   id, name, alias?, active, note?
Phrase    id, scope, text, items[]?, pinned, useCount, lastUsedAt, createdAt
  scope   场景键，见上表；pinned=false 即"最近"层
```

### 2.18 "组"要分两种，而且不能存成员快照（CONFIRMED，用户追问）

用户追问：能不能选一部分学生分成组，之后点组就行。

这个问法把"组"从名单的一个属性提升成了独立对象。但组有两种，来源不同，不能合成一个：

| | 排班组 | 点名组 |
|---|---|---|
| 例子 | 值日组、A/B 组、第一组 | "今天留下的 5 个人" |
| 谁定 | 岗位表 / 座位表 | 老师当场勾 |
| 变不变 | 按日期区间轮换 | 每次可能不同 |
| 成员从哪来 | 实时查 `Role.people` | 存 `memberIds` |

#### 红线：组只存"成员从哪来"，不存成员名单的快照

如果组里复制一份"A 组 4 个人"的名字，某天老师把倒垃圾的人从张三换成李四，岗位表变了、组里没变，屏上就出现两个版本。

这和课表存时间（2.1）是同一个错误：**存了派生数据，就必然有一天不同步。** 所以 `source:role` 的组只存组名（`roleGrp`），成员每次实时取。

#### 上屏：默认写组名，点一下看人（用户已确认）

| 状态 | 屏上表现 |
|---|---|
| 收起（默认） | `值日组 · 擦黑板、扫地`（组名 + 事项，不占行） |
| 展开 | 组名下方一行小字：张三、李四、王五 |
| 自动收起 | 10 秒无操作；切换时间块也立即收 |

三条约束：

1. **展开是只读交互**，不需要验证码，也不出现任何编辑控件——学生可以点，点了只能看
2. 展开区只在值日条内向下长出一行，**不覆盖五张卡**
3. 每进入新的时间块立即收起，避免上一节的名单留在屏上

为什么允许学生点：他点开是为了确认"是不是我"。拦住它，学生会转去问同桌，反而更吵。

#### 临时组不要存

"今天留 5 个人补作业"明天就不成立。这类组用完即弃，不落库。只有老师主动点"存成组"才进 `PeopleGroup`，并且必须命名。

理由和"最近话术"一样：**不主动收藏的东西，系统自己攒，最后全是废条目。**

#### 数据结构

```
PeopleGroup  id, name, source(role|manual), roleGrp?, memberIds?[], order
```

`source:role` 只用 `roleGrp`（如"值日组"），成员实时取；`source:manual` 用 `memberIds`。两者互斥，不允许同时填。

### 2.19 P1 落地时又抓出三处（CONFIRMED，实测）

把真实数据填进 `data/*.json` 并跑通 `tools/build_day.py`，文档又被纠正了三次：

| # | 文档原写 | 实际 | 后果 |
|---|---|---|---|
| 1 | 一天 20 个块 | **21 块**（7+4+1+1+6+2） | 验收①的计数是错的 |
| 2 | 放学 17:10 | 第 20 块到 17:20 | 差 10 分钟，两种解释都成立，未确认 |
| 3 | 黑板清洁师"1–6" | 1–5 是周一到周五，6 是替补 | 原型把 6 当第六天，陈静姝永远轮不到 |

第 3 条我一开始判断错了。看到 6 个人配 5 个上学日，我推断"只能是按天顺延、每周错位"，于是改成 `unknown` 等老师给起始日。老师纠正：**数字就是星期几，陈静姝是特殊情况来帮忙的替补。**

所以正确模型是 `peopleMap`（显式 5 天映射）+ `substitute`（常备替补），不是轮换。这条同时说明两件事：

1. 2.11 的红线仍然成立，但成立方式是"**存显式映射**"，不是"不存映射"。老师确认过就落库，没确认才留空。
2. **"数据对不上"有两种可能**：规则比想象复杂，或者有一个人根本不在这个序列里。我默认了前者。5 个位置配 6 个人，第一反应应该是"多出来的是不是替补"。

现在数据里存 `peopleMap{1-5}` + `substitute[陈静姝]`，`rotation.status:"confirmed"`，P1 按周几取到正确的人。

另外三个模型缺口，是填数据时才发现的：

- `freq` 少了 `task` 类（擦窗户挂在大扫除上，不是独立时点），实际需要 7 类
- `weekRule` 原来只挂在整张课表上，但周五第 7 节是**条目级**单双周，必须下沉到 `Entry`
- `Role` 缺 `substitute`：常备替补和"某段日期换人"是两回事，前者不占排班位

四条改动没有一条是设计时想到的。这就是"真实数据当检验"的实际产出：**它不是在验证你写对了，是在告诉你哪里写错了。**

### 2.20 大屏视觉规范（CONFIRMED，用户定调）

用户提出的要求：面向五年级学生，不能全是信息，要有突出重点；字体、动效要符合该学段；紧急情况用红色流光。

#### 先说现有页面错在哪（不是"不好看"，是"读不到"）

现在 `app/index.html` 是文档式排版：米白底、深灰字、细边框。作为一份"通知"是得体的，作为教室里挂 8 小时的屏是失效的。四个具体问题：

| # | 问题 | 证据 |
|---|---|---|
| 1 | 主区有 5 个字号层级（10 / 4.4 / 3.2 / 2.9 / 2.6vmin） | 3 米外一次只能分辨 3 层。层级超过 3 个 = 没有层级 |
| 2 | 辅助字号 2.6–2.9vmin 只有前排能读 | 65 寸屏 1vmin≈0.81cm，2.9vmin≈2.3cm；后排 8 米处属于"看得见轮廓、认不出字" |
| 3 | 颜色不承担语义 | `--accent` 是棕色，用来标倒计时和提示。棕色既不表示"快"也不表示"注意" |
| 4 | 状态切换没有任何信号 | 学生低头写作业，抬头才发现已经上课了。全靠自己瞟时钟 |

#### 学段特征：五年级要的不是"可爱"

10–11 岁已经有"不想被当小孩"的意识。低年级那套大圆角、泡泡字、卡通插画，在这个年纪会被嫌弃，反而降低权威感。

**目标不是"可爱"，是"被认真对待"**。所以视觉方向是：干净、有力、有秩序感，靠**色块、字号跨度、留白**制造重点，不靠插画和字体装饰。

对应四条约束：

1. **颜色即意义**：不用装饰色。每个颜色只对应一种"现在能不能动"。
2. **一屏一件事**：主区只说"现在该干什么"，其余全部下沉到条带。
3. **指令要具体**："安静"不如"手放桌上"——五年级能读长句，但不会自己把抽象词翻译成动作。
4. **不公开批评**：公屏点名批评对这个年纪的伤害远大于低年级。这条已经是红线，视觉上也要体现——没有"警告某人"的红色卡片。

#### 三色语义（提案）

| 颜色 | 含义 | 用在 |
|---|---|---|
| 绿 | 可以动、可以说话 | 课间、午餐、放学后 |
| 蓝 | 专注、不要打断 | 上课、眼保健操（闭眼） |
| 琥珀 | 准备、还有一会儿 | 课间最后 2 分钟、课前准备、午间收尾 |
| 红 | **立刻停下手上事** | 见下 |

#### 红灯必须稀缺（这是最容易被做坏的一条）

一天有 13 次状态切换。如果每个"快上课了"都红光流光，一天闪 13 次，第三次之后学生就免疫了，真正的紧急也不会有人抬头。

**规则：红光只给"必须立刻中断当前行为"的场景，一天上限 2–3 次。**

候选场景（待用户勾选）：

- 上课铃响、人还没回座位 → 强候选
- 老师临时发的紧急通知（"现在全部到走廊集合"）→ 强候选
- 大课间上下楼 / 体育课集合 → 更像"注意"，倾向琥珀
- 眼保健操开始 → 是"闭眼"，不是"紧急"，倾向蓝
- 放学整队 → 每天固定，会脱敏，倾向琥珀或不用色

流光本身也要限时：只在进入该状态的**前 60 秒**流动，之后定格为静态红边框。持续流动 40 分钟会让人烦躁，也会让一体机风扇更响。

#### 字号：从 5 级压到 3 级

| 级 | 用途 | 建议 | 现在 |
|---|---|---|---|
| L0 | 主指令（"现在去接水"/"第 6 节 语文"） | 12–14vmin，字重 700 | 10vmin |
| L1 | 上下文（下一节是什么、任课老师） | 5–6vmin，字重 500 | 4.4vmin |
| L2 | 辅助（值日条、提示） | ≥3.4vmin，字重 400，颜色降饱和 | 2.6–2.9vmin |

原来的 `kicker`（小标签）与 `h1` 合并成一行"第 6 节 · 语文"，`sub` 与 `meta` 合并成一行，`note` 与 `items` 合并成"动作 + 清单"。**合并不是删信息，是把 5 个视觉层压成 3 个。**

#### 字体：不能引入字体文件

一体机可能离线、可能没有装思源黑体。引入 webfont 会让包体从 300KB 涨到 5MB+，还会在冷启动时闪字（FOUT）。

所以视觉张力只能靠这四样，不靠字体：

- 字号跨度（L0 : L2 ≥ 3.5 倍）
- 字重（400 / 500 / 700 三档，系统字体都有）
- 色块（实心圆角块 vs 透明背景）
- 数字用等宽（`tabular-nums`，倒计时不跳位）

#### 动效：三条硬规则

1. **只在状态切换时动，不做常驻循环**。入场 400ms 上浮 + 淡入，仅此一次。
2. **倒计时数字每秒变化就是动效**，不再加缩放/弹跳。
3. **必须能关**。`prefers-reduced-motion` 自动降级 + 右上角手动"减少动态效果"开关。教室屏连续开 8 小时，动效是负担不是加分。

红色流光是唯一允许的持续动效，且限时 60 秒（见上）。

#### 定稿（用户已选）

| 决策 | 选择 | 影响 |
|---|---|---|
| 基调 | **清爽有力**：浅色底 + 大色块 + 字号跨度，不做卡通插画 | 白天教室光照强，浅底比深底清楚；避开"幼稚化" |
| 结构 | **一屏一件事**：主区只有一个巨大焦点，其余下沉到条带 | 后排一眼能读 |
| 红光 | **只给老师手动发的紧急通知**（未选"上课铃""集合""放学"） | 见下，这是最重要的一条 |
| 屏 | 75 寸 | L0 基准 22vmin（≈20cm 字高） |

#### 由此推出一条硬规则：系统永不自动变红

用户没有把"上课铃响没回座位"选进红光。这条比看起来重要：**红色全部来自人为触发，所以屏上的红永远可信。**

如果系统自己判断"紧急"（迟到了、快上课了），它一定会误报——迟 10 秒就红、走廊堵一下就红。红一旦被误报消耗掉，真出事时没人抬头。

于是：

- 系统只产出 绿 / 蓝 / 琥珀 三色，**没有任何代码路径能自动进入红色**
- 红 = 老师在编辑面板里勾了"紧急"，且 60 分钟后自动失效
- 课间收尾、集合、放学整队一律用琥珀，不用红

#### 焦点随时间转移（不是静态排版）

一屏一件事不等于一屏一个样。同一段课间：

| 时段 | 主角 | 字号 | 配角 |
|---|---|---|---|
| 刚下课 0–2 分钟 | 「课间」 | 22vmin | 喝水 / 上厕所 / 准备下节课的书 |
| 中段 | 「课间」 | 22vmin | 下一节 数学 · 李老师 |
| 最后 2 分钟 | 「1:47」 | 26vmin | 后上课 · 下一节 数学 |

这才是"动效符合学段"：不是加动画，是**让屏上的主角按时间换人**。学生每抬头一次，看到的重点都不一样。

眼保健操不进倒计时——闭着眼做操，屏上跳数字只会让人偷看。

#### 字号：从 5 级压到 3 级

| 级 | 用途 | 落地值 | 旧 |
|---|---|---|---|
| L0 | 主焦点（"课间"/"第 6 节 · 语文"/倒计时/紧急通知） | 22–26vmin，按字数与面积反算 | 10vmin |
| L1 | 上下文（下一节、任课、时长） | 5.2vmin | 4.4vmin |
| L2 | 辅助（值日条、动作 chip） | 3.2–3.5vmin | 2.6–2.9vmin |

原来的 `kicker` 与 `h1` 合并成顶栏色块 + 主焦点，`sub` 与 `meta` 合并成一行"下一节 数学 · 李老师"。**合并不是删信息，是把 5 个视觉层压成 3 个。**

L0 不写死：`textSize()` 按字数与可用面积反算，2 个字和 40 个字占同样的视觉重量。

#### 字体：不能引入字体文件

一体机可能离线、可能没装思源黑体。引入 webfont 会让包体从 300KB 涨到 5MB+，冷启动还会闪字。

所以视觉张力只靠四样：字号跨度（L0 : L2 ≥ 6 倍）、字重（400/500/700/800）、色块、等宽数字（`tabular-nums`，倒计时不跳位）。

#### 动效：三条硬规则（已落地）

1. **只在状态切换时动**：入场 420ms 上浮 + 淡入，仅一次。每秒重播会让人分心。
2. **倒计时数字每秒变化就是动效**，不再加缩放/弹跳。
3. **必须能关**：`prefers-reduced-motion` 自动降级 + 右上角"减少动效"手动开关，两条都生效。

红色流光是唯一允许的持续动效，且**只在头 60 秒流动**，之后定格为静态红边（持续流动 40 分钟会让人烦躁，也会让一体机风扇更响）。

### 2.21 视觉重构：把动效收集器的做法搬进教室屏（DONE）

用户评价"前端太丑"，要求参考 `motion-effects-collector`（本人 GitHub 仓库，42 条动效）与开源组件设计。重构不改任何节律判断，只换表达层。

#### 借的是"做法"，不是"配色"

| 借来的 | 具体做法 | 用在哪 |
|---|---|---|
| 发丝线 + 面 | 1px `rgba` 边框代替阴影堆叠；阴影只在悬停时出现 | 值日条、提示条、按钮 |
| 等宽字承担仪表信息 | `ui-monospace` + `tabular-nums` + `.06em` 字距 | 日期、时刻、倒计时、小标签 |
| 三种缓动、四种时长 | `.22,1,.36,1` / `.16,1.02,.3,1` / `.4,0,.2,1`；160/340/520/800ms | 全站，不再随手写 `ease` |
| 交错入场 | 子元素 `animation-delay: i*55ms` | 动作提示 chips |
| 数字翻滚（number-ticker） | 每位一列竖排 0-9，`translateY(-d em)` + 弹簧缓动 | 倒计时 |
| 边缘流光（edge-glow） | 锥形渐变 + 环形 mask，只画在边缘 | 紧急通知红框 |
| 呼吸光（breathing-glow） | 只动 `transform/opacity`，3.6s | 当前时段脊柱、状态圆点 |
| 轻提示（toast） | 上浮 18px → 轻微过冲 → 停住 | 老师发的普通通知 |

#### 三处结构性改动

1. **左侧"一日脊柱"**：把原来一条纯色竖条换成按真实块比例排布的 21 段，当前段呼吸发光，游标随时刻滑动。学生抬头能同时知道"现在是什么"和"今天走到哪儿"。
2. **层级从 5 级压到 3 级**：22（主）/ 4.6（辅）/ 3.1vmin（标签），其余全部改等宽小字。层级多于 3 个等于没有层级。
3. **倒计时不再是一串数字**：滚轮逐位变化，个位转得最快，视觉上"在走"，比每秒重绘文字更稳（也避免每秒重播入场动画——原来 sig 里含秒数，这是个真 bug）。

#### 特意没借的

| 没做 | 原因 |
|---|---|
| 卡片跟随鼠标的柔光 | 教室是触摸屏，没有光标；手指划过反而误触发 |
| 粒子场 / 极光流体 | 静态装饰，挂 8 小时只会变成噪音和额外功耗 |
| 玻璃拟态大面积使用 | 浅色底上等于没有边界，远看一片糊 |
| 深色作为唯一主题 | 白天开灯 + 窗光会反光；做成可切换，默认浅色，用户自己判断 |

#### 新增：主题切换

右下角 `⋯` → `深色/浅色`，存 `prefs.theme`。`?theme=dark` 只用于调试，不写偏好——避免把教室屏改花。深色不是简单反色：语义色整体提亮（绿 `#2ED3A0`、蓝 `#7C9CFF`、琥珀 `#F2B34B`、红 `#FF5C5C`），标签底字改用深色墨水色。

### 2.22 师生通道：只做「老师发消息」，走局域网（CONFIRMED）

用户三项决定：**一体机只能连校园内网** / **学生留言暂不做** / 将来做的话署名由学生自选。

#### 先划清能力边界

局域网方案下，"老师不在教室也能通知"只在**校内**成立。老师在家、在路上发不了。P4 的目标描述从"远程通知"改成"**从校内任何地方发**"，不能含糊成"随时随地"。

这不是妥协的产物，而是这个班的网络事实。硬要做远程就得走公网，公网意味着学生数据出校，与"未成年人信息本地优先"冲突，收益也不值这个代价。

#### 通道长什么样

一体机跑一个常驻小服务，手机连同一 WiFi 用浏览器访问：

```
老师手机 ──WiFi──> 192.168.x.x:8765 ──> messages.json ──SSE──> 大屏
```

| 端点 | 用途 |
|---|---|
| `GET /` | 手机发送页 |
| `GET /screen` | 302 到 `/app/index.html`，大屏的同源入口 |
| `GET /app/*` | 托管大屏静态文件（防止路径穿越） |
| `GET /api/ping` | 大屏启动时探测，通了才接入；同时返回 `lan`（服务自己的局域网地址） |
| `GET /api/stream?since=n` | SSE 推送；`since=-1` 表示只收新消息，不回放 |
| `POST /api/messages` | 写入一条 |
| `GET /api/messages?n=5` | 手机端回看最近 5 条 |

大屏有两种打开方式，两种都留着：

| 方式 | 好处 | 代价 |
|---|---|---|
| `file://` 打开 `index.html` | 服务没跑也能用，拷过去就行 | 跨域，需服务端放行 `*` |
| `http://127.0.0.1:8765/screen` | 同源，连得上就一定通 | 必须服务在 |

#### 手机端只做一个动作

> 2026-11 追加：让别的老师也能用，卡点不是功能而是「抄 IP」。
> 大屏点「⋯」→「手机」直接出二维码，手机扫了进发送页。
> 码用本地的 MIT 库生成（`app/vendor/qrcode.min.js`），不联网、不请求第三方。
> 地址取 `/api/ping` 的 `lan`；如果只拿到 `127.0.0.1`，手机根本连不过来，
> 这时**不画码**，改成「先启动服务」的操作步骤——扫不开的码比没有码更耽误事。

讨论稿里曾有"这条给谁看（全班 / 只给我自己）"，定稿删掉了。理由：老师给自己记东西不会用教室屏通道，手机备忘录更快；摆一个永远选"全班"的开关，只是增加一次点击。

`forWhom` 字段保留在协议里（`class` / `self`），大屏只渲染 `class`。这样将来真要加，不用改数据格式。

#### 关闭：时间不该是死的

原方案只有 10 / 20 / 30 三档自动过期，老师说完话只能等它自己没。实际上"现在到走廊集合"这种事，学生集合完就该撤，多留一分钟都是干扰。

时长改成五档 + 自定义：

| 选项 | 语义 |
|---|---|
| 10 分钟 / 30 分钟（默认）/ 1 小时 | 常规 |
| 自定义 1–180 分钟 | 不常用的时长 |
| **直到我关** | 不自动消失，但当天 23:59 兜底 |

"直到我关"必须有兜底。老师发完忘了撤，第二天早上屏上还挂着昨天的话，比没有通知更糟。23:59 是"当天结束"，不是业务时间，不会误导谁。

三条关闭路径，对应三个场景：

| 老师在哪 | 怎么关 | 设计理由 |
|---|---|---|
| 手机在手（最常见） | 手机页顶部「正在显示」条 → 撤回 | 一秒完成，且能先看见屏上是什么 |
| 站在大屏前 | 长按通知条上的 `×` **0.9 秒** | 单击无效。学生路过点一下不会把老师的话关掉 |
| 没网 / 服务没起 | 只能本地清 | 服务端本来也没这条，刷新不会回来 |

**紧急通知不放大屏关闭按钮**，只能从手机撤。理由：紧急通知的安全前提是"它一定被看见"，在屏上留一个关闭口子会削弱这个前提；而紧急通知本身有时长，到期自己消失。

`POST /api/retract` 不带参数，撤的是"最近一条未撤回、未过期的班级消息"。一次撤一条，不做批量——批量撤回在教室里没有使用场景。

#### 消息格式与本地完全一致

服务端产出的就是 `overrides[date].notice` 那个结构：

```json
{ "text": "现在到走廊集合", "level": "urgent",
  "at": "14:32", "until": "14:42", "createdAt": 1762321920000 }
```

服务端不引入新概念，只是把 `localStorage` 换成 HTTP。大屏收到后写回本地，后续渲染走原路径，**screen.js 一行不改**。

#### 大屏不被绑死：探测 + 静默降级

| 情况 | 行为 |
|---|---|
| 服务在 | 连 SSE，接手机消息 |
| 服务不在 | 静默走本地，和现在完全一样，不报错、不提示 |
| 连上又断 | 保留最后一条直到 `until` 过期，角标不显示"断线"（教室里没人关心网络） |

这条保住了 P1–P3 最重要的性质：**老师拷一个文件夹过去就能打开**。服务是增强，不是前置。

#### 部署形态第一次变化（必须承认）

这是 P1 以来第一次打破"零依赖单文件"：一体机上要有一个常驻进程。

| 阶段 | 做法 | 门槛 |
|---|---|---|
| 先验证 | `python3 server/rhythm_server.py` | 一体机要有 Python（Windows 一般没有） |
| 再交付 | 打包成单个 `rhythm-server.exe`，托盘常驻、开机自启 | 双击即可，无需装任何东西 |

先做第一种，能跑通再打包。**不打包不做，因为没验证过的部署方式等于没做。**

#### 三个真实失败点

1. **IP 会变**。DHCP 换地址后老师书签失效。对策：一体机设静态 IP；服务启动时把当前地址打在大屏角落（只显示 10 秒，不给学生看）。
2. **老师手机连的是 4G**。最常见，且浏览器只会转圈。对策：发送页顶部常驻一行"教室网络 · 192.168.x.x"，连不上时这句话本身就不出现，老师能自己反应过来。
3. **服务没启动**。老师以为发了，屏上没反应。对策：发送页显示"已送达"仅当服务真的回了 200；否则明确报"没连上教室"。

#### 学生留言：设计留住，实现推迟（REJECTED for now）

用户选择暂不做。但设计结论保留，将来启用时不必重新讨论：

- 形态是**悄悄话**，不是留言板。屏上永远不显示内容，只显示条数。
- 入口是一个很淡的 ✉，不做成按钮——按钮会吸引刷牌。
- 内容 20 字以内，进去切遮挡页，提交后 3 秒退回，不占节律屏。
- 署名**由学生自己选**，默认匿名。强制匿名会招来恶意留言且无法回访；强制署名则最难开口的那类事一条都不会有。

理由记在这里：学生和老师同处一室时，"学生给老师发消息"是伪需求，当面说永远更快。成立的只有"不敢当面说"这一种。

### 2.27 交付形态：一个包 + 一个单文件（DONE）

`tools/package.py` 一次产出两种，都在 `dist/`：

| 产物 | 大小 | 含什么 | 给谁 |
|---|---|---|---|
| `示例节律屏-测试包-YYYYMMDD.zip` | ~110 KB | `app/` + `server/` + 三个 .bat + 使用说明 | Windows 一体机，要试手机发消息 |

### 2.29 设置能搬走，也能烤进包（DONE）
老师的修改在 `localStorage`，进程外读不到。所以补了双向通道：

- `Store.exportAll()` → `{"format":"rhythm-config/v1", texts, overrides, phrases, prefs}`，不导撤销栈。
- `Store.importAll()` 校验 `format`，不认识直接拒，不半途写入。

### 2.30 仓库与隐私边界（DONE）

公开仓库 `sulengyin/ClassBeat`，首版打 `v0.1.0-snapshot`。

**分开存放的三类东西：**

| 类别 | 位置 | 是否入库 |
|---|---|---|
| 真实班级数据（48 名学生、教师、校名） | `data/`、`assets/` | 否 |

页面文件里不许出现数据里那个班名。

所以 `git clone` 之后一条命令就能跑起来，不需要先准备自己的班级数据。

### 2.31 早读 8:10 结束、准备清单提前到课间、北京时间（DONE）

早读原来是从「到校后」到「第 1 节前」推算出来的一段，最大的问题是老师没法指定它几点结束。现在它是 `timetable.blocks` 里真实的一段：

```json
{ "seq": "0a", "start": "07:30", "end": "08:10", "type": "reading", "name": "早读" }
{ "seq": "0b", "start": "08:10", "end": "08:20", "type": "break",   "name": "课间" }
```

- 07:20–07:30：到校（交作业、整理书包；`marks.arrive` 由老师改）。
- 07:30–08:10：早读。读什么仍由 `texts.reading` 按星期配，没配就不猜科目，只显示「早读」。
- 08:10–08:20：课间，**从 8:10:00 第一秒起**投放第 1 节的准备清单。
- 08:20：第 1 节上课，准备清单撤下。

没有 `reading` 块的作息表（其他学校）仍走老的派生逻辑，不会因为升级就丢掉早读。

**二、准备清单只在紧邻上课的课间出现**

| 原来 | 现在 |
|---|---|
| 正课卡里列清单（level 3） | 正课卡不列清单 |
| 课间按 level 分三档：3/2 全程、1 最后 2 分钟 | 课间从第一秒就列，不分 level |
| 没到点只写「下节课的书」占位 | 没有清单就不写，不编物品 |

理由：学生需要整段课间去拿东西；等最后 2 分钟才说，等于没说。倒计时仍按原规则在收尾时接管主视觉，清单不消失。

**三、早读的「提醒事项」**

`texts.reminders` 按星期配，另有 `default` 兜底：

```json
"reminders": { "default": "戴好红领巾，打扫好个人卫生", "4": "今天穿校服" }
```

屏上是单独的黄色贴纸（`.reminder-line`）＋深色感叹号，排在早读建议前面。它比建议重要，所以不做成同一行；留空就不显示。编辑在「文字 → 早读 · 提醒事项」，每天一行。

**四、时间只认北京时间**

新增 `app/clock.js`，所有"现在几点/今天几号"都从这里取：

- 不读设备时区，固定用 `UTC+8` 换算（北京时间没有夏令时）。设备时区被设成 UTC 或别的城市，屏上时间仍然对。
- 局域网消息服务可达时，`/api/time` 返回毫秒时间戳，`Clock.sync()` 校准设备时钟偏差；超过 12 小时的偏差当坏数据拒绝，服务不在就继续用本机时间。
- 服务端 `at / until` 也改成按 `UTC+8` 算，消息过期判断不再受服务器时区影响。
- Playwright 钉住时钟时加 `?nosync=1`，避免被服务端时间拉回真实时刻。

测试：`tools/test_clock.js`（11 项）、`test_rhythm.js` 的 8:10 切换与提醒事项、e2e 的 08:10 用例。

### 2.33 配置向导：让别的老师配出自己的班（BUILDING 2026-11-07）

**为什么要有**：现在的包是"五5班的包"。别的老师拿到手，屏上是别人的班级、别人的作息、别人的课表。要改成自己的，得会改七个 JSON，或者跑 `bundle.py` + `package.py`——两样都不是普通老师会做的事。这一条直接挡住了"发给其他学校老师"。

**向导要解决的不是"改一个时间"**（那已经有作息页），是**从空白到这个班的屏**。四步，每步都能跳过：

| 步 | 填什么 | 默认值从哪来 | 为什么这样排 |
|---|---|---|---|
| 1 班级 | 学校名、班级名 | 「我的班」 | 决定包名、屏角文字、消息服务里的班级标识 |
| 2 作息 | 选一套模板，再改不一样的起止 | 三套模板：40 分钟课 / 35 分钟课 / 含午休 | 二十几个块逐个手填没人有耐心；**模板 + 差异**是唯一可行解 |
| 3 课表 | 5×7 网格填科目，任课老师可后补 | 允许留空，那格屏上显示「—」 | 35 格是数据本身的复杂度，能做的是少填，不是变没 |
| 4 岗位 / 文案 | 用默认，或改几条 | 通用岗位 + 现有文案 | 这一层最不影响"能不能用"，放最后，可整体跳过 |

**产出**：配置写进 `localStorage`，立刻生效；另有「导出我的班级」下载一份 JSON，换电脑时导入。

**关于"能不能在网页里直接生成 zip"**：这一步不做，理由不是懒。大屏是 `file://` 打开的静态页，浏览器不允许网页往磁盘写文件，更不允许它写出 `启动手机服务.bat` 和一个 Python 服务。真要"网页内一键出包"，得把整个 `server/` 当字符串内嵌进页面再用 JSZip 在前端拼包——体积和维护成本都不划算。**导出一个 JSON 是这一步的正确边界。**

**失败处理**：

- 相邻块首尾不接 → 保存时拒绝，并指到具体哪一段（沿用作息页的校验）
- 课表留空 → 不报错，那节显示「—」，与现在的行为一致
- 向导中途关掉 → 已填的存下来，下次从断点继续，不从头来
- 导入格式不认识 → 整个拒绝，不半途写入（沿用 `Store.importAll`）

**验收**：

- 一个没读过文档的人，10 分钟内从空白配出能用的屏
- 全程不用打开命令行
- 配完立刻能看「今天的时间线」预览，不用等到明天

**不做**：多班管理、账号体系、云端同步、拼音输入法。

### 2.34 手机消息不再要求装 Python（DONE）

**真机反馈**（2026-11-06，一体机）：双击「启动手机服务.bat」，窗口写「这台电脑没找到 Python 3」。这台机器是学校统一管的，装软件要审批——要求老师先装 Python，等于把这条路堵死。

三个方案摆在桌上：

| 方案 | 老师要做什么 | 包多大 | 代价 |
|---|---|---|---|
| 让老师装 Python | 下安装包、管理员授权、勾 Add to PATH | 160 KB | 过不了学校审批，且勾 PATH 这一步经常漏 |
| PyInstaller 打 exe | 双击 exe | +8 MB | 得在 Windows 上构建，本地是 OpenHarmony 做不了；杀软误报是常事 |
| **官方 embeddable 运行时** | 双击 bat | **+11 MB** | 包里多一份 Python |

选第三个：`python-3.12.10-embed-amd64.zip` 是 python.org 的官方产物，解压即用，不装、不改 PATH、不要管理员权限。`tools/package.py` 下载后按 SHA256 校验，解到 `server/python/`；bat 先看这个目录在不在，不在才退回系统 Python。

体积从 160 KB 涨到 10.8 MB。这是笔明白账：**11 MB 换掉一次审批**。只要看大屏的老师仍用单文件版（214 KB），不受影响。

想自己控制体积就打 `python3 tools/package.py --no-python`，包回到 160 KB，但一体机得自己装 Python。

**顺带修的两个坑**：

1. 上一版 bat 用 UTF-8 + `chcp 65001` 写中文，cmd 在 65001 下逐行解码会错位，把「安装第一屏…勾上 Add Python to PATH」那行拆开，后半截当成命令执行，屏上直接报 `is not recognized as an internal or external command`。改成 GBK 写盘（中文 Windows 的原生代码页 936），双字节字符都 >127，不会被误判成 `& | >`。
2. bat 里探测 Python 的顺序改成 `py -3` → `python`：官方安装包的 launcher 最可靠，而 Windows 自带的 `python.exe` 可能只是个跳应用商店的 stub。

**没验证**：Windows 上 embeddable 运行时的实际表现（本机跑不了 exe）。间接验证做了两项——官方包里 `http.server`、`socketserver`、`ssl`、`sqlite3` 等 599 个标准库模块齐全；服务端在 `python3 -I -S`（隔离模式，等价于没有 site-packages）下 ping、发消息、取消息全部正常。

### 2.35 手机消息改成卡片弹窗（DONE）

**真机反馈**（2026-11-06，一体机）：消息能到，但顶栏那条 2.9vmin 的便签，8 米外最后一排看不清。老师发「现在去走廊集合」，前排动了，后排还在看课表。

改成屏中央展开一张卡片：

| 决定 | 理由 |
|---|---|
| 宽高一起过渡，**不用 `scale`** | `scale` 会把汉字压扁，笔画比例全变；改宽高才是"卡片长大" |
| 26×16vmin → `min(124vmin, 86vw)`，高按内容实测、封顶 80vh | 短句不留一大片空，长句不被裁；4:3 和竖屏也顶不到边 |
| 遮罩 `rgba(26,17,10,.5)` + `backdrop-filter: blur(7px)` | 背后还在走的作息退成底图，字才压得住；旧内核不支持模糊也至少变暗 |
| 字号按视觉宽度分五档：8 / 7 / 5.8 / 4.9 / 4.2vmin | 手机端上限 60 字，最长一档也放得下；中英混排按权重算，不按字符数 |
| 关闭 = 按住 0.9 秒 | 和通知条的 × 同一约定，学生路过点一下不会消失；按钮直接写「按住关闭」，旁边一行小字说明。Esc 也能关 |
| 关闭同时撤回 | 清本地 notice + `POST /api/retract`，否则刷新一次又回来 |

**只在 fresh 时弹**：`Remote.apply(msg, fresh)`；开机从 `/api/messages` 恢复的那条传 `false`，只贴便签。否则早上发的通知，中午重启大屏会再吓全班一次。

**没验证**：真机上的 blur 开销、4:3 屏的实际留白，等下一次一体机测试；e2e 已加"卡片不碰边 + 正文 ≥28px"的断言。

## 二、由真实数据反推的 13 条硬约束

1. **课表与作息彻底解耦**，唯一连接键是「节次编号」。课表只写"第 N 节上什么"，时间永远查作息表。
2. **作息是"块序列"**，不是"上课/下课"布尔值。渲染必须能处理仪式、空档、午休、课后服务。
3. **课间有 4 种**，提示内容完全不同：
   - 大课间（升旗）：排队、下楼、仪式
   - 大课间（活动）：热身、安全
   - 眼保健操：闭眼、坐姿、5 分钟倒计
   - 普通空档：喝水、如厕、准备下节课
4. **6 段课间必须显式建模**。不能让状态机在 10:15–10:25 这种时段返回"无数据"。已确认统一显示「课间」，数据层仍保留 break 类型。
5. **需要周次规则与张老师字段**。单双周、选修地点，不能靠老师口头记。
6. **内容包只需 12 条**，不是 35 条。这是"前期单班、后期复制"的成本基础。
7. **倒计时必须逐段可配，不能是全局开关**。课后服务倒计时会让学生等着放学；眼保健操倒计时会让学生在闭眼时偷看屏幕；上课倒计时会催着学生看表。默认策略见第四节。
8. **一天是"锚点 + 槽位"，不是固定块列表**。锚点由学校作息决定，槽位由班主任决定；**槽位的时间范围也必须可改**，写死在代码里就等于把学校规定当成了产品规定。
9. **没有"值日表"这个对象，只有"岗位"**。每个岗位自带时间规则、换人方式、执行顺序；"值日表"只是它们的视图。两张真实表结构不同，硬塞进一个模型必然要丢信息。
10. **频率是岗位属性，且有 5 类加一类"没写"**。每节课、每天 N 次、每周固定日、按事件、周期轮换；表上没写的必须留空，**不许默认为"每天"**。
11. **凡是靠猜的，都要老师确认一次**。通知原文不能直接上屏（2.4），"1 后跟人名"的私有编码不能直接解析（2.11），替补给谁不能自动填。这条出现三次了，已经是方法论。
12. **岗位有顺序，且顺序由班主任定**。放学 6 件事不能并列刷屏，要压成 3 步；但"先扫地还是先关窗"是班里的习惯，系统推不出来。
13. **编辑态必须与大屏显示态隔离**。老师输入的任何内容、弹出的任何人名候选，在按下保存前不得出现在大屏可见区域；进入编辑先切遮挡页（见 2.17）。

## 三、数据模型（v0）

```
Term            学期：id, name, startDate, endDate
TimetableVer    作息版本：id, effectiveFrom, name, blocks[]
  Block         id, seq, name, type(class|ritual|break|meal|noon|after),
                start, end, periodNo?, slotId?
  Slot          可变槽位：id, kind(break|meal|noon), start, end, title, tip, items[],
                weekdays[], editable(start|end|title|tip|items)
NoonRule        午间周规则：weekdays{1-5: presetId}, defaultPreset,
                band{lunchEnd, bell, noonEnd}   ← 三个可调分界点，见 2.8
DayOverride     当天覆盖：date, noon{preset,start,end,title,tip,items}, dutyTeacher
SchoolNotice    学校通知：from, to, scope, title, tip   ← 优先级最高，班级端不可覆盖
ScheduleVer     课表版本：id, effectiveFrom, weekRule(all|odd|even|range), entries[]
  Entry         weekday(1-5), periodNo, subject, teacher, place?, note?,
                weekRule?(odd|even)                        ← 单双周是条目级，不是表级
Role            岗位：id, name, duty, freq, people, substitute, order, assign, grp
  freq          {kind: each|daily|weekly|event|cycle|task|unset,
                 times[], weekdays[], event, task}          ← task 是"挂在大扫除上"的那类
  people        names[]  |  peopleMap{1-5: name}  |  groups{A, B}
  substitute    names[]，常备替补；不占排班位，请假时才顶上
  assign        fixed | self-organize        ← 派单还是只召集
  order         同一时刻的执行顺序，班主任定
  grp           大屏上合并成同一条的分组名，如「值日组」
RoleSetVer      岗位版本：id, effectiveFrom, group(A|B), roles[]
Substitution    替补：roleId, dateFrom, dateTo, fromName, toName, permanent
Override        当日覆盖：date, kind(swap|cancel|extra), payload   ← 临时调课/特殊日
Student         学生名单：id, name, alias?, active, note?           ← 只停用不删除，见 2.17
PeopleGroup     人群组：id, name, source(role|manual), roleGrp?,
                memberIds?[], order                                 ← 只存来源，不存成员快照，见 2.18
Phrase          班级话术：id, scope, text, items[]?, pinned,
                useCount, lastUsedAt, createdAt                     ← pinned 区分"记住/最近"两层
ContentPack     内容包：subject → {items[], level(0-3), place?, tip}
```

红线：
- `ScheduleVer` **不含任何时间字段**
- 所有班级差异只进 `ContentPack` / `Slot` / `Override`，不进代码
- **锚点时间班级端不可改**，只能整体切换作息版本
- **槽位时间班级端可改**，但必须过验证码、必须留痕、必须能一键还原
- 槽位的边界受锚点约束：午间最早 11:40（午餐开始），最晚 13:00（下午第一节）
- 解析优先级固定为 `SchoolNotice > DayOverride > WeekRule > Default`，任何页面不得绕过
- 编辑权按「角色 × 时段」切分：班主任可改整周规则，中午看护老师只能改当天，学生只读
- **学生记录只停用不删除**，`Phrase` 与内置话术分开存储，升级不覆盖老师写的内容
- **组不存成员快照**：排班组只存 `roleGrp`，成员每次从岗位实时取（同"课表不存时间"）

## 四、渲染规则

```
state(t)   = blockAt(t)
target(t)  = 从当前块向后找第一个「需要动作」的块（跳过 break）
screen     = f(current, target, schedule(today), contentPack)
```

五张卡：

| 当前块 | 大屏显示 | 倒计时对象 |
|---|---|---|
| 上课 | 安静模式：节次 + 科目 + 教师（低干扰） | 下课 |
| 课间 | 下一节科目 + 准备清单 + 一句提示 | 下一块开始 |
| 固定仪式 | 仪式名 + 要求 | 仪式结束 |
| 午餐 | 安静吃饭 + 饭后收拾 | 午餐结束 |
| 午间安排 | 槽位标题 + 任务清单 + 下午第一节要带的东西 + 看班老师（不显示来源） | 午间结束 |
| 课后服务 | 时段名 + 要求 | 本段结束 |

**值日条（独立于五张卡，常驻屏幕底部）**

```
此刻值日  值日组 · 扫地、后柜窗台、包干区、倒垃圾（4 项） → 节能小队长·吕雨桐 → 路队长·孙星野
```

- 只在有岗位触发时出现，最多 3 条
- 同组多件事合成一条，否则放学一口气刷 6 条没人看
- 按 `order` 排序，前 3 步之外显示"还有 N 步"
- `unset` 频率的岗位永不上屏

**倒计时策略（逐段可配，不是全局开关）**

每个块带两个参数：

```
countdown: off | untilEnd | untilNext     // 是否倒计、倒计到哪
showFrom:  N                              // 只在剩余 N 分钟内出现
```

默认配置：

| 块类型 | 默认 | 出现在 | 理由 |
|---|---|---|---|
| 上课 | 关 | — | 学生不该盯下课时间，大屏保持安静 |
| 大课间 / 升旗 | 关 | — | 30 分钟太长，倒计无意义，只显示流程 |
| 眼保健操 | 关 | — | 只有 5 分钟，闭着眼不该看屏 |
| 课间 | 开 | 最后 10 分钟 | 距离上课 |
| 午餐 | 开 | 最后 5 分钟 | 提醒收拾桌面，不要拖到午间 |
| 午间 | 开 | 最后 10 分钟 | 距离午间结束；结束后接课间，再报距离上课 |
| 课后服务 | 关 | — | 避免"还有 80 分钟放学"的催促感 |

老师侧提供三档全局模式：**按推荐 / 全部显示 / 全部关闭**，默认「按推荐」。
「全部关闭」也要保留：有些班主任不希望屏幕上出现任何数字。

## 九、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 内容包三个月后没人更新 | 产品失效（同类产品真正死因） | 内容包与课表分离，改内容不动代码；首次配置由班主任一次填完 |
| 作息中途调整 | 节律全错 | 作息版本化，按生效日期切换 |
| 临时调课频繁 | 显示错误 | P3 的"今日覆盖"必须 60 秒能改完 |
| 提醒过密导致麻木 | 学生不再看屏 | 上课期间完全安静；每课间只给 1 条提示 |
| 大屏被关机/切源 | 无法显示 | 开机自启 + 状态持久化 + 恢复后立即对齐当前时间 |
| 电脑时钟不准 | 全盘偏移 | 时间固定按 UTC+8 换算；局域网服务可达时每 10 分钟校一次，偏差 >12 小时当坏数据拒绝 |
| 高频岗位常驻，屏幕变噪音 | 「此刻值日」沦为背景，其他提醒一起失效 | 每节课的岗位只在课间最后 2 分钟出现；总量超过 3 条就必须合并（见 2.14） |
| 表上没写的频率被系统补全 | 学生白跑、老师失去信任 | `unset` 一律留空，不上屏，教师端明确列出"还没设时间"的岗位 |
| 岗位表手写改动无处落 | 老师放弃维护，改回纸质表 | 支持单条改人 + 替补 + 临时/长期标记，绝不要求整表重填 |
| 18 个岗位变成 18 条配置 | 初始化成本高到没人愿意做 | 提供真实表的导入模板；导入时对"1 后跟人名"这类私有编码要求确认一次，不自动猜 |
| 名单录入卡住 | 初始化成本高，后面全不做了 | 名册已到（48 人），直接预置；转学生用粘贴补录 |
| 名单与岗位表姓名不一致 | 候选里出现不存在的人，或任务派给查无此人 | 外部导入的姓名一律拿名册比一次，剥掉"（替补）"这类备注；已实测抓出 4 个错字（12%），差异列出来让老师点一次 |
| 历史话术无限膨胀 | 候选比手打还慢，功能变累赘 | "记住"必须老师勾选；每场景上限 12 条；"最近"自动滚动只留 5 条 |
| 老师忘了退出编辑 | 大屏长时间停在遮挡页，学生不知道现在该做什么 | 编辑态 3 分钟无操作自动保存草稿并退出；遮挡页常驻当前时间与"还有 N 分钟下课" |
| 编辑内容被投到大屏 | 当众点名、公开批评，家长投诉 | 遮挡页硬隔离（第 13 条硬约束）；补全候选与输入框同一层渲染，不进大屏层 |
| 学生翻看名单或话术 | 姓名与评语外泄 | 编辑入口需验证码；名单与话术只在编辑态可读，退出即卸载 DOM |
| 组里存了一份成员名单 | 换人后屏上显示旧成员，老师失去信任 | 排班组只存 `roleGrp`，成员实时取；`source:role` 与 `memberIds` 互斥 |
| 值日条展开后被学生一直点开 | 遮挡卡片、名单长期挂在屏上 | 10 秒自动收、切块必收；展开区只在值日条内生长，不覆盖五张卡 |
