# 从 0.3.x 升到 0.5.x（跨代升级）

> 适用：装在老师机器上的是 0.3.x（网页版 / 解压即用），要换到 0.5.x（安装包）。
> 一句话：**不能自动升，手动装一次就行，班级数据用「导出 → 导入」搬，不会丢。**

---

## 1. 为什么断在这里

两个形态几乎每一层都不一样，不存在一条自动通道：

| | 0.3.x（网页版） | 0.5.x（桌面版） |
|---|---|---|
| 怎么装 | 解压 zip 到文件夹，双击 `大屏全屏.bat` | NSIS 安装包，装到本机用户目录，不要管理员密码 |
| 跑什么 | `pythonw` 起 Python 服务 + `Chrome --kiosk` | Tauri 壳 + WebView2 + Rust 服务（`classbeat-server.exe`） |
| 数据在哪 | 浏览器 `localStorage`（跟着 origin 走） | 同一套 `localStorage`，但 origin 换了 |
| 怎么更新 | 服务读 `main/update.json`，下载 zip、**逐文件原位替换** | Tauri updater 读 Release 的 `latest.json`，**装签名过的安装包** |
| 怎么卸载 | 删文件夹 | 设置 → 应用 |

关键在"怎么更新"这一行：0.3.x 的更新器只会在自己的文件夹里换文件，它没有安装
NSIS 包的能力；0.5.x 的更新器签的是安装包，不会去替换散文件。两边清单格式也不同
（`update.json` schema 1 vs `latest.json` 的 `platforms.*`），所以**跨代只能手动一次**。

仓库根目录的 `update.json` 现在是一份**跨代公告**（`schema: 2`）。0.3.x 检查更新时会看到：

> 更新清单格式版本是 2，这个版本的程序只认 1；请先手动更新

这是有意为之：老版本能看懂"别再尝试自动升级了，去手动装"。以前这个文件被删了，
老版本报的是「连不上更新服务器，请检查网络」——把版本问题说成网络问题，反而更误导。

## 2. 三步搬过来

### 第一步：在旧的那台上导出设置

大屏右下角 `⋯` → **编辑** → 拉到最下面「导出设置」→ 得到 `五年级1班-设置.json`。

这份 JSON 里有班级、作息、课表、岗位、文案、本机偏好，是整份设置。

> 数据不在安装文件夹里，在浏览器 `localStorage` 里。所以**别用"拷文件夹"的方式备份**，
> 拷过去也是空的；只有这份导出的 JSON 或者手机/网盘上存的一份才是真的。

### 第二步：装新版

从 [Releases](https://github.com/sulengyin/ClassBeat/releases/latest) 下
`ClassBeat_版本号_x64-setup.exe`，双击。装到本机用户目录，不需要管理员密码，
装完桌面有图标。

装之前不用卸载旧版，但建议把旧的 `大屏全屏.bat` 从开机自启里去掉，否则两边会抢屏。

### 第三步：把设置导进新版

第一次打开会进配置向导。**第一步就有一个「导入旧设置 JSON」**，选第一步存的那个文件：

- 导入成功后自动跳到最后一页，点「完成」收工，哪一步都不用填；
- 导入前会校验文件格式，失败一个字都不改。

漏了这一步也不要紧：以后从 `⋯` → 编辑 → 最后一页「导入设置 JSON」同样能补。

---

## 3. 版本对不上会怎样

- **0.3.x 读 0.5.x 的设置**：能读。导出格式从 0.1.0 起就是 `rhythm-config/v1`，
  一直没变过（`app/store.js` 的 `EXPORT_FORMAT`），字段只增不改。
- **0.5.x 读 0.3.x 的设置**：能读，同上。
- **导入时提示"设置来自更新的版本"**：说明文件是更高版本导出的，
  老程序不敢猜新字段。先升级本机再导入。

---

## 4. 装完之后

- **以后不会再断代**：0.4.0 起都是安装包形态，更新走 Tauri updater
  （右下角 `⋯` → 更新 → 检查更新），装完数据不变，健康检查不过会自动回滚。
- **确认两个版本号**：`⋯` → 更新面板里，前面是安装包版本（跟 Releases 标签一致），
  括号里是界面版本。两个都对才说明更新成功。
- **回滚**：面板里「回滚到上一版」在更新过、且留有备份时才亮。

## 5. 常见问题

**Q：旧版已经卸掉了 / 电脑重装了，还能救吗？**
数据在浏览器里，跟着浏览器配置走。同一台机器、同一个浏览器、同一个地址（端口）再打开
0.3.x，`localStorage` 还在，能重新导出。换过端口、换过浏览器或清过缓存就没了——
这也是 0.3.x 一直提醒"一个月导出一次"的原因。

**Q：能不能让 0.3.x 的用户自动跳到下载页？**
技术上要出一个"桥接版"（用旧更新器把页面换成带下载按钮的版本，再让老师点一次安装包），
仍然要点那一下。收益是多一个按钮，代价是往老形态里再塞一次未验证的自动更新——
2026-11-19 就因为清单与白名单口径不一致，让所有自更新卡死过一次。所以不做，
改用"检查更新给出明确结论 + 首次启动就能导入"这两条。

**Q：学校是批量部署，几十台怎么办？**
安装包是 perUser 的，可以静默装（`/S`），也可以把导出的 JSON 一起发下去；
导入那步在向导第一步，一条路径，不用一页页点。
