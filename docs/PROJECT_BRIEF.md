# 班级大屏节律终端 · 定位与边界 v0.2

> 状态：CONFIRMED 部分为用户已确认；ASSUMED 部分待验证；PLANNED 为已决定未实施。
> 真实数据：示例小学作息表、五（1）班课表（已归档于 `assets/source/`）。
> 详细计划见 `PLAN.md`，低保真预览见 `preview/day-rhythm.html`。

## 一、一句话定位

面向小学班主任的**班级节律终端**：把作息表、课表、值日表编译成"此刻该做什么"，在教室大屏上自动呈现。单班起步，配置化设计，可复制到其他班级与学校。

不把自己定义成"通知工具"或"电子班牌"——那两类已有免费开源实现和多个商业竞品。

## 二、用户与场景

| 角色 | 关系 | 首版权限 |
|---|---|---|
| 班主任 | 配置者、维护者、付费决策者 | 全部 |
| 任课教师 | 查看、临时调课 | 有限编辑 |
| 学生 | 被动接收 | 只读 |

关键场景：课前 2 分钟、课间 10 分钟、午休、放学前 5 分钟、临时调课/代课。

## 二点五、真实数据带来的结论（CONFIRMED）

1. **课表与作息表已经打架**：第 4 节课表写 11:20–11:30，作息表写 11:20–11:40。→ 课表不得存时间，只存节次与科目。
2. **一天是 20 个时间块**：7 节正课 + 4 个固定仪式（2 次眼保健操、2 次大课间）+ 1 段午休 + 6 段无名空档 + 2 段课后服务。
3. **课间有 4 种**：升旗大课间、活动大课间、眼保健操、普通空档，提示内容完全不同。
4. **6 段"空档"就是课间**（10:15–10:25、11:05–11:20、12:50–13:00、13:45–13:55、15:40–15:50、16:30–16:40）。作息表没写"课间"二字，但它们是真实间隔，必须显式建模。
5. **需要周次规则与张老师**：周三第 4 节选修张老师，周五第 7 节双周轮换。
6. **内容包只需 12 条**（35 格归并后），这是可复制的成本基础。
7. **倒计时逐段可配**：默认只出现在课间最后 10 分钟、午休最后 10 分钟；上课、眼保健操、课后服务一律不显示。另提供「按推荐 / 全部显示 / 全部关闭」三档。

## 三、目标与非目标

### 首版目标（P1–P3）

1. 三表导入（Excel 模板）与页面微调
2. 时间状态机：课前预备 / 上课 / 课间 / 午休 / 放学 / 特殊日（考试、调休、放假）
3. 课间卡：下节课 + 准备清单 + 倒计时 + 一条安全提示
4. 断网可用，离线跑完一整天
5. 大屏端现场修改 + 防误触验证
6. Windows 与安卓浏览器同源呈现

### 首版明确不做

- 老师在校内发消息到大屏（二期，走局域网；学生留言已推迟，见 PLAN 2.22）
- 多班管理、校级集控、教务系统对接
- 考勤、积分、作业、成绩
- 原生 App、微信小程序
- AI 问答、语音助手

## 四、核心模型

```
三张表 → 时间状态机 → 规则 → 动作 → 大屏渲染
```

- **作息表**：节次、起止时间、课间/午休标记
- **课表**：周次 × 星期 × 节次 → 科目 / 教师 / 地点
- **值日表**：周次 × 星期 → 岗位 / 人员
- **规则**：触发（时间点 / 节次事件）+ 条件（年级、单双周、特殊日）+ 动作（卡片 / 倒计时 / 语音 / 滚动）
- **内容包**：科目→准备物品、安全提示库、习惯用语库，按年级替换

### 硬性架构约束

1. 班级差异**全部进数据（配置 + 内容包），不进代码**。这是"前期单班、后期复制"的唯一可行解。
2. **一天 = 锚点 + 槽位**：锚点（节次、仪式、课后服务）由学校作息定，班级端不可改；槽位（课间、午餐、午间）由班主任定，可改但要过验证并留痕。
3. **大屏只说学生语言**。学校通知、行政术语、系统状态、来源标注一律不得出现在屏幕上；外部文字上屏前必须经教师改写确认。
4. **编辑权按「角色 × 时段」切分**。验证码只防误触，不承担越权防护。

## 五、首版验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 断网连续 8 小时，状态切换误差 ≤ 5 秒，无空白 | 拔网实测 |

| 7 | 学校通知上屏前，必经一次教师改写，无"一键转发"路径 | 检查交互流程 |

## 六、技术决策

- 前端 Web + PWA，全屏 kiosk；不做原生，保证两端同源代码
- 单班模式：一台常开设备（教室一体机或办公室小主机）跑服务端 + SQLite；二期可切云
- 实时通道：SSE，断线自动重连（比 WebSocket 简单且够用）
- 时间：启动校时 + 每日校准，不信任浏览器时区与系统时间
- 部署：Windows 浏览器全屏自启；安卓 PWA 全屏 + 屏幕常亮

## 七、复用结论（基于公开资料核对）

| 方案 | 结论 | 理由 |
|---|---|---|
| class-assistant（MIT） | 不做底座，做需求样本与数据模型参考 | 一体机端是 Python tkinter 桌面程序，非 Web，无法满足两端同源、页面可编辑、小学视觉 |
| ClassIsland（GPL-3.0） | 不集成，参考提醒交互与课表模型 | 桌面端、无远程下发；GPL 对后续商用有约束 |
| SchoolAnnouncements | 参考 SSE 多屏同步与集中管理 | 架构可借鉴，场景是国外数字标牌 |
| class-assistant 部署思路 | 借鉴 | 云 / 局域网双版本，契合校园网络现状 |

## 八、风险清单

1. **课表高频变动**（调课、代课、临时活动）→ 必须有"今日临时调整"，且 60 秒内完成
2. **大屏被学生当玩具** → 默认只读、编辑入口隐藏、角色权限；验证码只防误触，不防故意
3. **单班模式依赖一台常开设备** → 开机自启、断电恢复、状态持久化
4. **内容维护衰减** → 内容包必须"一次配置长期复用"，否则三个月后无人更新（同类产品真正死因）
5. **未成年人信息** → 本地优先、最小采集；留言默认不上公屏（二期）
