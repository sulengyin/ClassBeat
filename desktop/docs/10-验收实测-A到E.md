## 10.6 这轮修掉的 6 个真问题（都是"装上去才发现"的）

| # | 现象 | 根因 | 改法 |
|---|---|---|---|
| ① | 静默装完：有卸载项、有注册表、**就是没有 classbeat.exe** | `NSIS_HOOK_PREINSTALL` 里 `SetOutPath $TEMP` 之后没复位，安装段后面几百条 `File` 全解到 `%TEMP%` | 宏尾统一 `SetOutPath $INSTDIR`；并在 POSTINSTALL 加"主程序必须在"硬自检 + 弹框/日志 |
| ② | 清场脚本一次都没生效（`退出码=1`） | `stop-legacy.ps1` 存成 **UTF-8 无 BOM**，PS 5.1 按 ANSI 解中文 → `ParserError: 字符串缺少终止符` | 文件改成 UTF-8 **带 BOM**，并用 `Parser::ParseFile` 验证 0 语法错误 |
| ③ | 更新/重装后**桌面图标凭空消失** | PREINSTALL 无条件删 `$DESKTOP\ClassBeat.lnk`；而 Tauri 模板的 `CreateOrUpdateDesktopShortcut` 在更新模式（`$UpdateMode=1`）直接 `Return`，没人重建 | 只在"确实从 0.3.x 升上来"时删；POSTINSTALL 自己 `CreateShortCut`（幂等） |
| ④ | 升级后每次开机都报错 | 0.3.x 的自启 .lnk 真名是 `ClassBeat 大屏自动恢复.lnk`（指向已删除的 watchdog），按固定名字删根本没删到 | 改成 `FindFirst/FindNext` 通配扫 `*ClassBeat*.lnk` 与 `*节律*.lnk`，逐条删并写日志 |
| ⑤ | 每启动一次多一个 `reg.exe` 子进程；在被管控的机器上 `os error 5`，自启静默失效 | 开机自启靠 `Command::new("reg")` | 换成 `windows` crate 直接调 `RegSetValueExW/RegQueryValueExW`：无子进程、无窗口，另加一个 `#[ignore]` 的真机往返单测 |
| ⑥ | perUser 安装却去写防火墙，要多起 `net`/`netsh` 两个外部进程；被安全软件拦时会连带打断安装 | 钩子无条件走防火墙分支 | 按 `INSTALLMODE` 编进去：`currentUser` 不编译这段；卸载同理，并去掉 `schtasks`（0.3.x 从来没用过计划任务） |

另外两处小修：`latest.json` 生成脚本原来会挑错版本（目录里躺着多个包时按名字排序取第一个）→ 改成按 `--version` 过滤；
更新日志 `更新已交给安装器` 写在 `install()` 之后（那条路径 `process::exit(0)`，永远执行不到）→ 挪到前面。

## 10.7 新增风险 / 待决（按严重度）

1. **未签名的 exe 会被 Defender 直接处置（最高优先级，且不止调试版）**
   实测 `Trojan:Win32/Bearfoos.A!ml`，ThreatID 2147731250，命中
   `%LOCALAPPDATA%\ClassBeat\classbeat.exe`；快捷方式与 Run / Uninstall 注册项也被连带扫过。
   **先前"release 构建跑得住、只有调试构建必被拦"的结论是错的**，02:00 之后拿正式 release 包（SHA256
   `FD4E8383…`，5,204,480 字节）复测，一样被命中，时间线见下表：

   | 时间 | 事件 | 表现 |
   |---|---|---|
   | 1:49:46 | 1116 检测 + 处置 | 安装器刚把 exe 落盘 |
   | 2:00:34 / 2:00:42 | 1116 + 1117 | 启动即被拦，进程 1–2 s 内消失 |
   | 2:00:44 / 2:00:52 | 1116 | 同上（无提示、无窗口、`/api/ping` 无响应） |
   | 2:01:02 → 2:01:19 | 1116 → 1117 | 同上；这次连「ClassBeat 壳 … 启动」都没写进日志 |
   | 2:06 起 | 无新事件 | 同一文件连续两次启动都正常，服务在听 —— 云端判定延迟下来后暂时放行 |

   结论：**判定不可预测**，这比"稳定失败"更危险——老师头一天看着是好的，第二天开机可能就被删了，
   而且没有任何提示。发布前必须 Authenticode 签名 + 向微软提误报（07 的 P5，这次是实测命中，不再是
   "理论上可能"）。教室侧若要临时放行，只有"管理员把安装目录加 Defender 排除（需先关篡改保护）"这一条，
   属过渡手段，不能写进交付说明。
2. **旧版僵尸进程（本机特有）**：0.3.24 的 `pythonw.exe`（PID 6896，17:30 以管理员权限启动）杀掉要提权，
   普通权限 `Stop-Process`/`taskkill` 都是"拒绝访问"。它占着 8765，导致新装顺延到 8766。
   同一个来源还有一个以管理员身份跑着的 `powershell`（旧 `watchdog.ps1`）。两者一起把
   `%LOCALAPPDATA%\ClassBeat` 里的旧 `server\`、`tools\launcher\` **锁住**，`RMDir /r` 删不掉 →
   `check_install.py` 的 C2（旧装目录已清）/ C5（无旧看门狗进程）到现在还是红的，**只靠重启能清**。
   长期对策两条：① **本轮已落地**——`stop-legacy.ps1` 遇到"拒绝访问"不再只写日志（老师不会去看日志），
   而是留一个 `%TEMP%\classbeat-need-reboot.flag`，安装器收尾与卸载收尾都读它，弹一句
   "请重启电脑后再打开/再卸载"（静默安装不弹框、只写日志，避免更新流程卡住）；
   ② `RMDir /r` 之后补一句 `IfFileExists` 自检，删不干净就记日志 + 卸载项里留一行提示 —— **还没做**（见 08）。
3. **MSI 只适合 IT 批量**：WiX 是 perMachine，非管理员 `/qn` 返回 1925 → 1603；而且 MSI 没有 NSIS 那套钩子，
   装完**没有 App Paths / classbeat:// 协议**（自启项由应用首启自己补）。学校里要么统一用 NSIS，要么给 WiX 补自定义动作。
4. **D5 与设计冲突**：见 10.4。
5. **localStorage 迁移缺口**：见 10.3 末尾的补充。
6. **业务版本 ≠ 壳版本**：`resources/build-info.json` 是 0.3.24（`app/version.js`），卸载项/日志是 0.4.1。
   查问题时别混：设置→应用 看壳，页面/`/api/ping` 的业务字段看包。

### 这轮踩到的坑（花了 40 分钟，记下来）

**release 构建硬拒 http 端点，而且是以"闪退"的形式出现。**
按旧文档用 `--config` 把 endpoints 指到 `http://127.0.0.1:8799/latest.json` 出的包，
双击后**秒退、日志一个字都不写**（连"壳 0.4.1 启动"都没有）。查 WER 是 `c0000409`（fail-fast，子码 7），
把 stderr 重定向出来才看到真话：

```
panicked at src\lib.rs:120: 初始化失败: PluginInitialization("updater",
  "Error deserializing 'plugins.updater' ... The configured updater endpoint must use
   a secure protocol like `https`.")
```

`tauri-plugin-updater` 的 `validate_endpoints()` 在 **release** 下只认 https，debug 下仅告警。
所以本地源测试构建必须同时带 `dangerousInsecureTransportProtocol: true`：

```
npx tauri build --bundles nsis --config '{"plugins":{"updater":{"endpoints":["http://127.0.0.1:8799/latest.json","http://127.0.0.1:8798/latest.json"],"dangerousInsecureTransportProtocol":true}}}'
```

这一项**只许进测试构建**，生产 `tauri.conf.json` 里不能出现；验收后也确认过正式包里没有。
`accept_update.py` 的文档头已把这条和完整命令写进去，并改成可传参（`--old/--new/--port`）。

另外两点：
- **锁屏会让这类验收全假红**（合成按键到不了应用），`accept_update.py` 现在开头就探测锁屏并退出码 2；
- 本轮为了让基线能反复装，`src-tauri/target/release/classbeat.exe` 现在是 0.4.1 测试基线的二进制；
  正式产物（0.4.2 的 exe 已在两个安装包里）不受影响，下次构建会重新生成。
