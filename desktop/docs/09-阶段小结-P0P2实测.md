## 9.2 参考实现与 Tauri 2.12 / windows 0.62 的四处硬差异（08 §8.2 命中）

| # | 现象 | 处理 |
|---|---|---|
| 1 | `WebviewWindowBuilder` 在 2.12 上**没有** `on_window_event`（只有 `WebviewWindow` 有，且回调只给 `&WindowEvent`，不给窗口句柄） | `build()` 成功后调 `WebviewWindow::on_window_event`，闭包捕获 `AppHandle`，内部按 label 找回窗口 |
| 2 | `MessageBoxW` 的样式参数类型是 `MESSAGEBOX_STYLE`（bitflags），不是 `u32` | `ui::message_box` 形参改为 `MESSAGEBOX_STYLE`；`MB_OK \| MB_ICON…` 直接透传 |
| 3 | 07 文档写的 `windows 0.58` 与本地缓存/参考实现实际使用的签名不一致 | 改用 `windows = "0.62"`：`MessageBoxW(Option<HWND>, …)`、`RegisterHotKey(…, HOT_KEY_MODIFIERS, u32)`、`MC…STYLE` 三者与参考实现逐字相容 |
| 4 | NSIS 里 `${__FILEDIR__}` 在**宏**中等于主脚本目录（`target\release\nsis\x64`），`File "${__FILEDIR__}\stop-legacy.ps1"` 必然 "no files found" | 在 `hooks.nsh` 的 **include 顶层**把它固化成 `!define CB_STOP_PS1 "${__FILEDIR__}\stop-legacy.ps1"`（顶层时它等于 hooks.nsh 自己的目录），宏里只引用该 define；并加 `!if /FILEEXISTS` 硬校验，找不到就 `!error` 失败 |

> 第 4 条最初试了"上溯四级相对路径"，实测发现 include 顶层与宏内的 `__FILEDIR__` 语义不同，
> 才改成"include 时固化 + 宏内引用"，两种写法都不依赖 `CARGO_TARGET_DIR`。

另修一处**测试断言**（不是功能 bug）：`civil_from_days(20290)` 实为 2025-07-21，
原断言写 07-20（20289 才是 07-20）。已改为 20289/20290 双断言并补 2024-02-29 闰日用例。

| 检查项 | 实测 |
|---|---|
| resources 双布局容错 | 命中 `<exe>\resources\app`（02 §2.1） |
| 端口顺延 | 8765 被旧版占用 → 自动用 **8766**，窗口 URL 同步 |
| `/api/ping` | `shell=true`、`port=8766`、`class=五（1）班` |
| `/api/update/status` | `selfUpdate=false`，`blockedReason` 为「桌面版由 ClassBeat 应用统一更新…桌面版」 |
| 进程树 | `classbeat.exe` → `pythonw.exe`（唯一子进程，无 `conhost.exe`、无 `powershell.exe` 子进程） |
| 窗口标题 | `班级节律屏`（页面「最小化/退出」的窗口枚举链路原样可用） |
| 误关（WM_CLOSE 等价 Alt+F4） | 窗口 `visible` 1→0、进程存活、日志「没有退出标记，按误触处理：已收进托盘」 |
| 主动退出（写 `exit-request.flag` + WM_CLOSE） | 进程退出、`pythonw` 无残留、8766 释放、标记被消费、日志「准备退出：先停后台服务」 |
| 数据分离 | `messages.json`/`net.json`/`logs`/`backups` 全落 `CLASSBEAT_DATA_DIR` |

回归对照（仓库原版 `server/`，未打补丁）：`/api/ping` **无** `shell` 字段、`selfUpdate=true`
—— 旧行为一字未变。
