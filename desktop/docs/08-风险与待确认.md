## 8.2 Tauri 2 API 风险（参考实现里用到的、需要按实际版本核对的点）

这些不是"错了"，是"版本间可能不同"。第一轮 `cargo check` 报错的，按右列降级。

| 用法 | 可能的差异 | 降级方案 |
|---|---|---|
| `WebviewWindowBuilder::on_window_event(\|window, event\|)` | 回调参数可能是 `&Window` 或 `&WebviewWindow` | 改用 `tauri::Builder::on_window_event` 全局钩子，按 `window.label()` 过滤 |
| `TrayIconBuilder::show_menu_on_left_click(true)` | 早期 2.x 无此方法 | 去掉，改在 `on_tray_icon_event` 里手动 `menu.popup()` |
| `event.id.as_ref()` 取菜单 id | 可能需要 `event.id().0.as_str()` | 用 `if event.id == MenuId::new("open")` 比较 |
| `Image::from_bytes(include_bytes!("*.ico"))` | 需要 tauri feature `image-ico` | 改用 PNG（同时加 `image-png`），或 `app.default_window_icon().cloned()` |
| `app.updater()` / `update.download_and_install(on_chunk, on_finish)` | 2.0~2.5 间签名有调整 | 降级为"只 check，然后 `ui::open_url(下载页)`"——能力仍在，只是要老师点一下 |
| `tauri::Url::parse` + `WebviewUrl::External` | `Url` 可能需要 `use tauri::Url`（重导出） | 加 `url = "2"` 直接依赖，用 `url::Url` |
| `app.run_on_main_thread(move \|\| ...)` | 闭包需 `Send + 'static`，捕获 `AppHandle` 可以 | 改为在 setup 里就创建窗口，服务就绪后再 `show()`（会先白屏，不推荐） |
| `tauri_plugin_single_instance::init(\|app, argv, cwd\| ...)` | 2.1 起回调参数数量稳定为 3 | 用 `_` 忽略多余参数即可 |
| `bundle.resources: ["resources/**/*"]` | 打包后可能多一层 `resources/` | `Paths::discover` 已容错两种布局；也可改对象映射形式 |
| NSIS 里 `${__FILEDIR__}` 定位钩子同级文件 | 取决于 Tauri 生成 installer.nsi 的位置 | 改成绝对路径，或把 `stop-legacy.ps1` 改成 `bundle.resources` 里的资源并在 POSTINSTALL 时复制 |

**处理原则**：先让 `cargo check` 过，再让 `tauri build` 过，最后才真机。不要一边调 API 一边调 NSIS。

## 8.3 必须在真机复测的 WebView2 行为

页面在 Chrome kiosk 里跑通了，不代表在 WebView2 里一样。逐项过：

- [ ] 字体与排版（一体机常有"微软雅黑"以外的替换字体）
- [ ] 触控滚动、长按菜单、双指缩放（kiosk 下应被禁用）
- [ ] 音频（若有提示音）：WebView2 的自动播放策略
- [ ] `window.print()`（若页面用到打印作息表）
- [ ] 剪贴板写入（"复制手机地址"之类）
- [ ] SSE 长连接在 WebView2 里被挂起/丢弃时页面能否自愈重连
- [ ] 120 分钟不操作后页面是否被节流（后台标签页节流在 WebView2 里也存在，需实测）

## 8.4 开工前要确认的 8 件事

1. 教室一体机的 Windows 版本与 WebView2 是否存在（**最要紧，决定路线**）；
2. 老师装软件有没有管理员权限（决定 perUser / perMachine 默认）；
3. 学校是否用组策略/联管平台批量装（决定 MSI 优先级）；
4. 是否采购 Authenticode 证书（预算与主体）；
5. 有没有第二块屏/投影切换的真实场景（窗口策略按这个定）；
6. "注册"是否只指系统注册（若是授权/激活，另立项目，见方案文档附录 A）；
7. 更新源域名现在是否可用（`update-source.txt` 里的加速域名）；
8. 这一版是否允许顺手改交互（建议**不允许**，只换壳，便于定位回归）。

## 8.5 两个决策门

**G0（P0 结束）**：≥2/3 台机器 WebView2 可用 + 空壳在真机能全屏触控 + 旧配置能自动恢复。
不通过 → 只做"安装器止血"（Inno Setup 重写安装包，约 4 人日），不换壳。

**G1（P2 结束）**：杀软、体积、内存是否还有投诉。
没有 → 停在 Python sidecar，不做 P4（省 12~15 人日），把预算投到多班管理（ROADMAP P4）。

## 8.6 实施后新增的风险（2026-11-21 实测，证据见 `10-验收实测-A到E.md`）

| 风险 | 实测表现 | 对策 |
|---|---|---|
| **未签名 exe 被 Defender 按 ML 启发式处置（不止调试版）** | `Trojan:Win32/Bearfoos.A!ml`（ThreatID 2147731250）命中 `%LOCALAPPDATA%\ClassBeat\classbeat.exe`。**正式 release 构建同样被命中**：Defender 操作日志 1:49:46（安装落盘）与 2:00:34 / 2:00:42 / 2:00:44 / 2:00:52 / 2:01:02（每次启动）各记一条 1116，2:01:02、2:01:19 执行处置；被处置的那几次进程 1–2 秒内消失、无任何提示、`/api/ping` 无响应。跑过若干次之后（02:06 起）同一个文件（SHA256 `FD4E8383…`，5,204,480 字节）两次启动都没再触发新检测、服务正常——**判定是云端延迟下来的，不可预测** | 发布前必须 Authenticode 签名（07 P5 硬门槛）+ 向微软提误报（wdsi 文件提交，报检测名）。教室侧只能由管理员临时把安装目录加排除（要关篡改保护），只当过渡手段。**绝不能靠"多跑几次就放行"交付**：老师头一天看是好的，第二天开机可能就被删了 |
| 旧版以管理员权限启动时，安装器杀不掉它 | 0.3.24 的 `pythonw`（PID 6896）`Stop-Process`/`taskkill` 全拒；占着 8765 → 新装顺延 8766 | **已落地**：清场脚本遇"拒绝访问"留 `%TEMP%\classbeat-need-reboot.flag`，装/卸收尾弹框提示"重启后再用"（静默安装只记日志）；`RMDir /r` 的删不干净自检仍未做 |
| MSI 是 perMachine | 非管理员 `/qn` → 1925 → 1603；且 MSI 没有 NSIS 钩子（无 App Paths / `classbeat://`） | 学校批量用 MSI（提权/GPO），老师自装用 NSIS；要齐套就给 WiX 补自定义动作 |
| 06 的 D5（强杀主进程 40 秒自动回来）与 02 的模块清单冲突 | 新方案没有看门狗，杀了就等下次登录 | 二选一：加常驻监督进程，或把 D5 改成"下次开机/双击回来" |
| 0.3.x 的配置有一半在浏览器 localStorage | 文件迁移只接得住服务端 `backups/config` 快照；刚改完就升级的场景可能丢最后一次改动 | 升级前强制同步一次快照，或加读旧 profile 的迁移器 |
