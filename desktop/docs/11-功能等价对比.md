# 11 · 功能等价性对比（旧解压版 vs Tauri 桌面版）

> 📌 **本文比的是"打包方式换了，业务有没有变"（0.4.x）。** 0.5.0 把服务也换成 Rust 之后，
> 又多了一层"Python 服务 vs Rust 服务"的端点级对比，结论与证据在
> [`12-服务从Python迁到Rust.md`](12-服务从Python迁到Rust.md)。
> 本文里 `equivalence_run.py` 等脚本名照留不追改。

> 一句话结论：**业务功能没有因为重构而改变**。108 个可交互要素、33 次真实点击、3 页整屏文本、8 个接口，
> 旧包与"新包代码 + 旧业务文件"逐项一致；差异只剩两类——版本号里的 build 段、以及一个新增的状态字段。
> 唯一老师能直接感觉到的变化是**更新入口从页面搬到了托盘/热键**，属设计替代，能力没丢。
>
> 跑的时间：2026-11-22 00:10–00:35，同一台机器（Win11 26200 / 非管理员）。
> 脚本：`desktop/scripts/equivalence_run.py`、`equivalence_probe.cjs`；原始数据 `desktop/dist/equivalence/`。

## 11.1 怎么做才叫"比过了"

只跑一份 e2e 说明不了等价——必须把两套东西**同时**跑起来，同一套动作各自做一遍，然后逐项对结果。
所以设计了四个互不干扰的实例（端口/目录/数据全隔离，不碰老师正在用的那一份）：

| 侧 | 代码来源 | 启动方式 | 端口 | 作用 |
|---|---|---|---|---|
| **A** | 旧包原件（0.3.24 解压版备份） | 自带 python 起 `rhythm_server.py` | 8785 | 基线 |
| **B** | 新包代码，但 `screen.js`/`edit.js`/`edit.css` 换回 v0.3.24 | 同上（不设任何 `CLASSBEAT_*`） | 8786 | 隔离出"重构"这一个变量 |
| **C** | 新包现状（= 0.4.1 实际装的东西） | 同上 | 8787 | 看旧包之后新加的业务改动 |
| **D** | 新包 + `CLASSBEAT_SHELL=1` | 同上 | 8788 | 老师实际使用的形态 |

- **A↔B** 回答"重构有没有改功能"（两边业务代码完全相同，只有打包方式不同）；
- **B↔C** 回答"旧包之后那三处业务改动带来了什么"（如实告知，不算回归）；
- **A↔D** 回答"壳模式让哪些东西变了"。

三侧的数据起点统一：都清掉 `messages.json`/`net.json`；A 侧另补一份与 C 相同的 `data/`
（旧包本身不带该目录，班级名会退化成中性的「班级」，那样比的就是数据而不是功能）。

## 11.2 证据一：代码层——差在哪，为什么差

### 前端 `app/`（23 个文件）

| 类别 | 数量 | 说明 |
|---|---|---|
| 完全一致 | 0 | — |
| **仅换行或 BOM 不同** | 18 | 旧包是 Windows CRLF、新包 stage 写成 LF。归一化后逐字节相同 |
| **实质不同** | 5 | 见下表 |

| 文件 | 旧 → 新 | 差异性质 | 判断 |
|---|---|---|---|
| `data.js` | 17,039 → 17,041 | 只有 `generatedAt` 时间戳（16:51:08 → 21:39:33） | 打包时间戳，非功能 |
| `version.js` | 594 → 608 | `BUILD` 从 `5ecb9e9` 变 `dev` | **真实缺陷**，见 11.10 |
| `edit.css` | 17,018 → 17,630 | 工作区未提交改动（+4 行） | 0.3.24 之后的业务改进 |
| `edit.js` | 71,663 → 77,318 | 同上（+81 行） | 同上 |
| `screen.js` | 45,311 → 47,304 | 同上（+23 行） | 同上 |

用 git 三方对齐可以确认这三处改动的归属：

| 文件 | 旧包 | git HEAD | 工作区 | 新包 resources |
|---|---|---|---|---|
| `edit.css` | `395d0a18` | `395d0a18` | `91514bc1` | `91514bc1` |
| `edit.js` | `e03458dc` | `e03458dc` | `105523f6` | `105523f6` |
| `screen.js` | `1af9fc8a` | `1af9fc8a` | `18c0281a` | `18c0281a` |

即：**旧包 == v0.3.24 的 HEAD；新包 == 当前工作区**。那三处是 2026-11-20 真机反馈之后
新做的"岗位里的人名从学生 id 解析成人名"，不是重构夹带。B 侧把这三处换回 HEAD，
就是为了把"重构"和"新功能"分开算。

### 服务端 `server/`（旧 45 个 / 新 8 个）

- **实质不同 2 个**：`rhythm_server.py`（+3,537 字节）、`updater.py`（+1,158 字节）；
- 仅编码不同 4 个：`phone.html`、`run.py`、`sw.js`、`update_manifest.py`（归一化后相同）；
- 只在旧包 37 个：内置 Python 运行时（现放 `resources/python`）+ `messages.json`/`net.json`（现放 `%APPDATA%\ClassBeat`）；
- 只在新包 0 个。

`rhythm_server.py` 与 `updater.py` 的改动逐条核对，就是 04 文档约定的 6 处定点补丁，**且全部由环境变量 gate**：

| # | 补丁 | 触发条件 | 不设变量时 |
|---|---|---|---|
| 1 | `_data_file()`：可写数据改到 `CLASSBEAT_DATA_DIR` | 环境变量非空 | 完全等于旧路径 |
| 2 | `BACKUP_DIR` 同样改到数据目录 | 同上 | 同上 |
| 3 | 退出大屏：壳模式写 `exit-request.flag` + 发 `WM_CLOSE` | `CLASSBEAT_SHELL=1` | 走旧 `stop.flag` + 看门狗交接 |
| 4 | `/api/ping` 增加 `shell` 字段 | 恒定输出（值为 `SHELL_MODE`） | 多一个字段，旧键不变 |
| 5 | 跳过 `watchdog_handover` 线程 | `CLASSBEAT_SHELL=1` | 照旧启动 |
| 6 | `updater.py`：`self_update_supported()` 返回 False + 壳模式提示语 | `CLASSBEAT_SHELL=1` | 照旧判断目录结构 |

这是本次等价性的设计基础：**不设变量，服务端行为与旧版逐行相同**。A↔B 的实测也证实了这一点
（B 侧全程未设任何 `CLASSBEAT_*`）。

## 11.3 证据二：可交互要素——一个不多、一个不少

探针把每页**所有**可交互元素找出来（`button`/`a[href]`/`input`/`select`/`textarea`/`[role=button]`/`[onclick]`/`[data-action]`/`[tabindex]`），
记录标签、类型、文本、id、class、可见性、尺寸；编辑面板是先点「配置班级」进入后再采一遍。

| 页面 | 要素总数 | 可见 | 实际点击 | 四侧是否一致 |
|---|---|---|---|---|
| 大屏 `/app/index.html` | 41 | 8 | 8 | 一致 |
| 编辑态（点「配置班级」后） | 48 | 15 | 14 | 一致 |
| 手机页 `/phone` | 19 | 11 | 11 | 一致 |
| **合计** | **108** | **34** | **33** | **一致** |

可见要素 34 个、点了 33 个，少的那个是编辑第一步里的「上一步」（`disabled`，本来就点不动），
**可见交互面覆盖率 97%，未点的那 1 个是禁用态**；另外 74 个隐藏要素（弹层、引导页、二维码面板）
通过"点开入口再采集"覆盖到，没有漏项。

A↔B 的要素集合差异只有 4 条，且是同一个原因：

```
只在 A：button 文本「更新v0.3.24 · 5ecb9e9」（大屏、编辑态各一条，且二者都 vis=False）
只在 B：button 文本「更新v0.3.24」
```

B↔C 的要素集合**完全相同**（108 个逐项对应，含文本与可见性）。

## 11.4 证据三：点击后果——33 次点击逐项对

每个元素点击前都回到同一初始状态，点击后比较：是否弹出确认框及内容、`body` class 变化、
可见元素数增减、可见文本长度增减、弹层数量变化、URL 是否跳转、控制台 error、页面级异常、
期间打出去的接口调用。

| 对比 | 都点过的元素 | 结果 |
|---|---|---|
| A ↔ B | 33 | 31 个完全一致；2 个差异（大屏与编辑态的「⋯」按钮），原因都是版本号里的 build 段 |
| B ↔ C | 33 | **33 个完全一致**（逐字段） |
| A ↔ D（壳模式） | 33 | 一致（差异在接口层，见 11.7） |

「⋯」那条差异的具体形态：点开后可见文本长度增加量 64 对 54，差的正好是 `" · 5ecb9e9"` 这 10 个字符
——同一个 build 号问题的第二个表现面，不是两个独立问题。

## 11.5 证据四：整屏文本——三页一字不差

整屏文本比对前先抹掉"必然不同但与功能无关"的噪声，否则每轮几十处假差异会把真问题埋掉：

| 噪声 | 归一化为 | 为什么 |
|---|---|---|
| `14:35`、`00:14` | `<T>` | 时钟每分钟在走 |
| 单独成行的 `:45` | `:<SS>` | 时钟的秒被拆到另一行 |
| `11月22日`、`2026-11-22` | `<DATE>` | 日期 |
| `127.0.0.1:8785`、`192.168.x.x:8765` | `127.0.0.1:<PORT>`、`<LAN>` | 四侧端口不同 |
| `1.55 ÷ 5 = ?` | `<Q>` | 编辑入口的"老师验证"算术题**每次随机生成**（防学生猜） |

归一化之后：

| 页面 | A ↔ B | B ↔ C | A ↔ D |
|---|---|---|---|
| 大屏 | 一致（152 字） | 一致（152 字） | 一致 |
| 编辑态 | 一致（291 字） | 一致（291 字） | 一致 |
| 手机页 | 一致（204 字） | 一致（204 字） | 一致 |

B↔C 也一致，说明那三处业务改动（人名解析）**在本机这份示例数据上不产生任何可见差异**——
因为示例数据的岗位里存的就是人名。它生效的前提是"岗位里存的是学生 id"，正是 11-20 那次
真机反馈的场景（"人名里混着英文字母串"）。这不是没测到，是这份数据不触发。

## 11.6 证据五：接口契约

8 个只读端点（`/api/ping`、`/api/time`、`/api/messages`、`/api/config/remote`、
`/api/config/remote/state`、`/api/update`、`/api/update/status`、`/api/config/backup`）：

| 对比 | 状态码 | 键集合 |
|---|---|---|
| A ↔ B | 8/8 相同 | 7 个相同，`/api/ping` 多一个 `shell` |
| B ↔ C | 8/8 相同 | 8/8 相同 |

`/api/ping` 新增的 `shell` 是**附加**字段（12 → 13 个键），旧键一个没动，老客户端按名取值不受影响。

> 这一条上一版差点判错：第一次采样时 A 的 `/api/config/remote/state` 返回 200、B/C 返回 404。
> 查下去是**采样顺序**问题——该端点依赖 `backups/config` 快照，而快照是大屏打开时才 POST 生成的；
> 我把接口采样放在打开页面之前，且 A 侧自带历史快照。把接口挪到页面之后采，三侧就一致了。
> 这类"环境/时序造成的假差异"必须自己先证伪，否则会把结论带偏。

## 11.7 壳模式审计：老师能感觉到的变化只有一处

`CLASSBEAT_SHELL=1` 与不设时，逐字段取 `/api/update/status`：

| 字段 | A 旧包 | D 壳模式 | 判断 |
|---|---|---|---|
| `selfUpdate` | **True** | **False** | 唯一实质语义变化 |
| `canApply` / `canRestart` / `state` / `message` | False / True / idle / 还没有检查更新 | 相同 | 一致 |
| `currentVersion` | 0.3.24 | 0.3.24 | 一致 |
| `build` | 5ecb9e9 | dev | 见 11.10 |
| `/api/ping` 键 | 12 个 | 13 个（+`shell`） | 附加字段 |

`selfUpdate=false` 会让页面进"单文件/由应用负责更新"分支（`app/update.js:160`、`:447`）。
壳模式把提示语换成了可执行的指引：

> 桌面版由 ClassBeat 应用统一更新：点托盘图标 → 检查更新（或按 Ctrl+Alt+U）

也就是说：**页面里那个"点一下就自己升级"的入口没有了，但升级能力搬到了托盘菜单和 Ctrl+Alt+U**。
老师少了一个入口、多了一个更稳的入口（带签名校验、失败不影响大屏）。这属于设计替代，
需要在交付说明里写清楚，不能假装没变化。

壳模式的另外两处差异在接口之外，属于实现细节但影响排障：

| 项 | 旧包 | 壳模式 |
|---|---|---|
| 数据位置 | 包内 `server/messages.json`、`../backups` | `%APPDATA%\ClassBeat\`（首启迁移） |
| 退出大屏 | `exit-kiosk.ps1` 杀进程 | 写 `exit-request.flag` + 发 `WM_CLOSE`，由壳优雅退出 |

## 11.8 桌面层交互面：6 个 bat 换成了什么

旧版老师面对的是桌面上一排 `.bat`，新版没有这些文件。逐项对应：

> 旧包还有 `五1班节律屏-测试包-单文件版.html` 与 `使用说明.txt`：前者是"单个 HTML 就能看屏"的另一种
> 分发形态（不含手机消息），新版不再提供——这属于分发形态的收敛，不是交互能力缺失。

| 旧交互 | 新交互 | 判定 |
|---|---|---|
| `启动手机服务.bat` | 启动壳时自动拉起（无需操作） | **等价，且更少一步** |
| `停止手机服务.bat` | 托盘「退出」/ `Ctrl+Alt+Q` 会连服务一起停 | 等价 |
| `打开大屏.bat` | 双击桌面图标 / 开机自启；已有实例时二次启动只是把大屏叫回来（单实例） | 等价 |
| `大屏全屏.bat` | 启动即全屏无边框（不再依赖 Chrome `--kiosk`） | 等价 |
| `打开演练版.bat` | 大屏上的「演练」按钮（可见要素，已点击验证） | 等价 |
| `退出大屏.bat` | `Ctrl+Alt+Q` → 确认框 → 退出；`Ctrl+Alt+M` 临时最小化 | 等价 + 新增最小化 |
| `安装开机自启.bat` | 安装器写 Run 项（`--autostart`），无需手工执行 | 等价 |
| （无） | 托盘菜单：检查更新 / 手机二维码 / 日志 / 退出 | 新增 |
| （无） | `classbeat://` 协议 | 新增 |
| （无） | 误关窗口收进托盘，而不是退出 | 新增 |
| 页面内「更新」面板（`selfUpdate=true`） | 面板改为指引，实际升级走托盘/热键 | **替代**（见 11.7） |

## 11.9 本轮发现并修掉的问题

1. **发布包自报 `build = dev`**（真实缺陷）
   影响：老师点「⋯」看到的版本号少了 commit 段（`v0.3.24` 而不是 `v0.3.24 · 5ecb9e9`），
   `/api/ping` 与日志里的 `build` 也是 `dev`，线上排障无法定位是哪次构建。
   根因：`stage_resources.py` 只把 git sha 写进了 `build-info.json`，没写 `app/version.js`；
   而页面读的是后者，且 `AppVersion.text()` 对 `dev` 有"省略"逻辑。
   修法：stage 时在**构建副本**上把 `BUILD` 重写为 `git rev-parse --short HEAD`（仓库里的 `dev` 不动）。
   已实测生效：重跑 stage 后 `resources/app/version.js` 的 `BUILD` 变为 `5ecb9e9`。
   **本轮重打包后已实测**：新 0.4.1 安装包的 `/api/ping` 报 `build=5ecb9e9`（装完再启动实测）；
   `verify_package.py` 也加了硬校验——构建副本里 `BUILD` 若还是 `dev` 直接 FAIL，
   免得这条再悄悄复发。

2. **对比方法自身的两个坑**（记下来防复发）
   - 接口采样必须先打开页面：`/api/config/remote/state` 依赖大屏首开生成的配置快照；
   - 文本比对必须先抹时钟/秒/日期/端口/随机验证题，否则几十处假差异。

## 11.10 没覆盖到的，以及残余风险

| 项 | 状态 | 说明 |
|---|---|---|
| WebView2 渲染内核 | **未逐像素比对** | 本报告的交互等价性在 Chromium（与 WebView2 同源）下测得；字体/抗锯齿/触摸滚动惯性属内核差异，靠验收 D 组（全屏 1512×950、触控）间接覆盖 |
| 真机触摸手势 | 部分 | 单指点击可自动化；双指、长按、滚动惯性需人眼，见 10 §10.4 |
| D7 拔网线 / D8 连续 3 天 | 未测 | 与本次等价性无关，仍挂在验收清单 |
| localStorage 迁移 | 已知缺口 | 0.3.x 有一半配置在浏览器 localStorage，文件迁移只接得住服务端快照；换壳后浏览器变了，这部分读不到。见 10 §10.3 |
| 编辑态 1 个 `disabled` 元素 | 未点击 | 「上一步」，禁用态，点不动是正确行为 |
