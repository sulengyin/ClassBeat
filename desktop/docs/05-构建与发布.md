# 05 · 构建与发布

## 5.1 环境

| 依赖 | 版本 | 说明 |
|---|---|---|
| Rust | 1.77+（stable，x86_64-pc-windows-msvc） | 需要 MSVC 生成工具（VS Build Tools） |
| Node | 18+ | 只用于 `@tauri-apps/cli`；也可 `cargo install tauri-cli` 完全不用 Node |
| Python | 3.10+ | 跑装配脚本与 `tools/bundle.py` |
| WebView2 | 系统自带（Win10 1803+ 一般有） | 打包时用 `webviewInstallMode` 兜底 |
| 签名 | Authenticode 证书 + minisign 密钥对 | 都放 CI secret |

## 5.3 装配步骤（`stage_resources.py`）

```
1. 复制 app/ → resources/app        （排除 __pycache__）
   复制 server/ → resources/server  （排除 messages.json / net.json / server.log / service.pid）
   复制 sample/ → resources/sample
   复制 data/（或 sample）→ resources/data
2. 生成 resources/app/data.js
   python tools/bundle.py --data <data> --out resources/app/data.js
3. 在 resources/server 副本上应用 6 处补丁（哨兵幂等 + 锚点缺失即失败，见 04 §4.3）
4. 解压 tools/vendor/python-embed-amd64.zip → resources/python（含 python.exe / pythonw.exe）
5. 写 resources/build-info.json（版本、build、装配时间、数据来源、运行时类型）
```

参数：`--data sample|data|<绝对路径>`、`--no-python`（开发期用系统 Python）、
`--check-only`（只校验锚点，不写文件）、`--clean`。

## 5.4 构建

```powershell
# 自检 → 装配 → 打包 → 打印产物
powershell -ExecutionPolicy Bypass -File desktop\scripts\build_windows.ps1

# 只自检
powershell ... -Check

# 内部发布：打真实班级数据
powershell ... -Data data
```

产物：

```
desktop/src-tauri/target/release/classbeat.exe
desktop/src-tauri/target/release/bundle/nsis/ClassBeat_x.y.z_x64-setup.exe
desktop/src-tauri/target/release/bundle/msi/ClassBeat_x.y.z_x64_zh-CN.msi
```

**发版前先把三处版本号同步改**（0.4.0→0.4.1 那次就是漏了一处，出现"安装器写 0.4.1、日志打 0.4.0"）：

| 位置 | 作用 |
|---|---|
| `src-tauri/Cargo.toml` 的 `version` | 壳自报的版本；**更新器拿来跟 `latest.json` 比的就是它** |
| `src-tauri/tauri.conf.json` 的 `version` | 安装包文件名、卸载项 DisplayVersion |
| `desktop/package.json` 的 `version` | 前端工具链/CI 里的一致性 |

业务侧版本（页面上那个 `v0.3.25`）在仓库 `app/version.js`，由 `stage_resources.py` 写进构建副本；
仓库里保持 `BUILD="dev"`，构建副本会被重写成真实提交号——`verify_package.py` 会拦住"构建副本还是 dev"的情况。

**本地更新源测试**要在构建时覆盖 endpoints，且 release 构建硬拒 http，必须同时打开
`dangerousInsecureTransportProtocol`（详见 10 §10.10；这一项不许进生产配置）。

## 5.5 开发循环

```powershell
powershell -ExecutionPolicy Bypass -File desktop\scripts\dev.ps1
```

- 数据目录指到 `%TEMP%\classbeat-dev-data`（随便删随便改，不碰老师的真实数据）。
- 改 Rust：`cargo tauri dev` 自动重编重启。
- 改前端/服务：重跑 `stage_resources.py`（或 `dev.ps1 -Stage`）后重启。
- 服务日志：`%TEMP%\classbeat-dev-data\logs\app.log` + `server.log`。

## 5.6 CI（建议新增 `.github/workflows/desktop.yml`）

现有 `release.yml` 跑在 `ubuntu-24.04` 上打 zip；Tauri 的 Windows 产物**必须**在 Windows runner 上构建。

```yaml
name: Desktop
on:
  push:
    tags: ["v*"]
  workflow_dispatch:

jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20" }
      - uses: dtolnay/rust-toolchain@stable
      - uses: swatinem/rust-cache@v2
        with: { workspaces: "desktop/src-tauri -> target" }

      - name: 自检（锚点/配置/模块）
        run: python desktop/scripts/verify_package.py

      - name: 装配资源
        run: python desktop/scripts/stage_resources.py --data sample

      - name: 构建（含签名）
        env:
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
        run: npx --yes @tauri-apps/cli@^2 build

      - uses: actions/upload-artifact@v4
        with:
          name: classbeat-desktop
          path: |
            desktop/src-tauri/target/release/bundle/nsis/*.exe
            desktop/src-tauri/target/release/bundle/msi/*.msi
```

## 5.7 更新链路

```
打 tag → CI 构建 → 生成 classbeat_<ver>_x64-setup.exe + .sig（minisign）+ latest.json
→ 上传到更新源（现有加速域名 + GitHub Releases 双源）
→ 客户端 tauri-plugin-updater 拉 latest.json → 验签 → 下载到 %APPDATA%\ClassBeat\backups\installers\
→ NSIS 被动安装（有进度条、无需点击）→ 应用重启 → 首启健康检查
→ 失败则用 backups/installers 里的上一版回滚
```

`tauri.conf.json` 里 `plugins.updater.endpoints` 先写占位地址，
`pubkey` 必须换成真实 minisign 公钥；否则"检查更新"会报错（不影响大屏）。
