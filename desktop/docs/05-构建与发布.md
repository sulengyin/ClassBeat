# 05 · 构建与发布

## 5.1 环境

| 依赖 | 版本 | 说明 |
|---|---|---|
| Rust | 1.77+（stable，x86_64-pc-windows-msvc） | 需要 MSVC 生成工具（VS Build Tools）；壳、服务、工具三份 crate |
| Node | 18+ | 只用于 `@tauri-apps/cli`；也可 `cargo install tauri-cli` 完全不用 Node |
| WebView2 | 系统自带（Win10 1803+ 一般有） | 打包时用 `webviewInstallMode` 兜底 |
| 签名 | Authenticode 证书 + minisign 密钥对 | 都放 CI secret |

**0.5.0 起构建链不需要 Python。** 装配/自检/更新清单/运行期验收全在 `desktop/tools-rs`
（`classbeat-tools.exe`）里，与壳、服务同一套工具链。

## 5.3 装配步骤（`classbeat-tools stage`）

```
0. 清掉 0.4.x 遗留的 resources/python（否则包会白白胖 22 MB）
1. 复制 app/ → resources/app        （排除 __pycache__ / *.pyc）
   复制 server/{phone.html,sw.js,icons} → resources/server
   复制 sample/ → resources/sample
   复制 data/（或 sample）→ resources/data
2. 把 resources/app/version.js 的 BUILD 从 dev 改成真实提交号
3. 生成 resources/app/data.js     （与 tools/bundle.py 的输出格式一致）
4. 拷 server-rs 编出来的 classbeat-server.exe → resources/server/
5. 写 resources/build-info.json（版本、build、装配时间、数据来源、"service":"rust"）
```

参数：`--data sample|data|<绝对路径>`、`--clean`（先清空 resources 再装配）、
`--check-only`（只校验，不写文件）。

**6 处源码补丁已退役**：服务是 Rust 之后，数据目录、绑定地址、菜单开关都从命令行参数进来，
`resources/server/` 里不再有需要打补丁的 `.py`（见 [`04-服务适配契约.md`](04-服务适配契约.md)）。

## 5.4 构建

```powershell
# 编译工具 → 自检 → 编译服务 → 装配资源 → 打包 → 打印产物
powershell -ExecutionPolicy Bypass -File desktop\scripts\build_windows.ps1

# 只自检（不编译、不装配）
powershell ... -Check

# 内部发布：打真实班级数据
powershell ... -Data data
```

也可以分步手跑，等价于脚本内部做的事：

```powershell
cargo build --release --manifest-path desktop\server-rs\Cargo.toml
cargo run --quiet --release --manifest-path desktop\tools-rs\Cargo.toml -- verify
cargo run --quiet --release --manifest-path desktop\tools-rs\Cargo.toml -- stage --data sample
npx --yes @tauri-apps/cli@^2 build
```

产物：

```
desktop/src-tauri/target/release/classbeat.exe
desktop/server-rs/target/release/classbeat-server.exe
desktop/src-tauri/target/release/bundle/nsis/ClassBeat_x.y.z_x64-setup.exe
desktop/src-tauri/target/release/bundle/msi/ClassBeat_x.y.z_x64_zh-CN.msi
```

**这里有两套版本，别再混着看**（0.5.0 出过一次真实事故：它俩写反了，面板上一直显示界面版本
`v0.3.25`，老师以为装的还是老包）：

| 谁 | 放在哪 | 拿来干什么 |
|---|---|---|
| **安装包版本** | `src-tauri/tauri.conf.json` 的 `version` | 安装包文件名、卸载项 DisplayVersion、**更新器跟 `latest.json` 比的就是它**、`build-info.json` 里的 `version` |
| **界面版本** | 仓库 `app/version.js` 的 `VER` | 只给老师看"界面是哪一版"；`stage` 原样带进构建副本，`build-info.json` 里的 `appVersion` |
| 壳/服务自报版本 | `src-tauri`、`server-rs`、`tools-rs` 的 `Cargo.toml`、`desktop/package.json` | 编译期注入的 `PackageInfo`、日志、CI 一致性；**不参与更新判断**，但必须与安装包版本同步改 |

规矩：发版只改"安装包版本"这条线（`tauri.conf.json` + 三个 `Cargo.toml` + `package.json` 一起升），
`app/version.js` 该不该动由界面改了多少决定。`classbeat-tools verify` 现在有一条硬断言：
`resources/build-info.json` 的 `version` 必须等于 `tauri.conf.json` 的 `version`（按文件新旧门控，
没装配时不误报）。页面上显示 `vX` 而安装包是 `Y`，就是这一条被绕过了。

`build-info.json` 的 `build` 字段是**装配那一刻的 `git HEAD` 短号**，装配时工作区有未提交改动
就会出现"包装好了但 build 号指向前一个提交"——发版流程因此固定成**先 commit，再出包**。

仓库里 `app/version.js` 的 `BUILD` 保持 `"dev"`，构建副本被重写成真实提交号——
`classbeat-tools verify` 会拦住"构建副本还是 dev"的情况。

**本地更新源测试**要在构建时覆盖 endpoints，且 release 构建硬拒 http，必须同时打开
`dangerousInsecureTransportProtocol`（详见 10 §10.10；这一项不许进生产配置）。

**两个 PowerShell 编码坑**（都踩过，改脚本时别再踩）：

1. `scripts/*.ps1` 必须存成 **UTF-8 with BOM**。Windows PowerShell 5.1 没有 BOM 就按 GBK 读源码，
   中文注释/提示会直接变成语法错误（`字符串缺少终止符`），脚本连第一行都跑不到。
2. 脚本开头要把 `[Console]::OutputEncoding` 与 `$OutputEncoding` 设成 UTF-8，
   否则 Rust 工具输出的中文在 GBK 控制台里是乱码（工具本身写的是 UTF-8，不改它）。

## 5.5 开发循环

```powershell
powershell -ExecutionPolicy Bypass -File desktop\scripts\dev.ps1
```

- 数据目录指到 `%TEMP%\classbeat-dev-data`（随便删随便改，不碰老师的真实数据）。
- 改壳（`src-tauri`）：`cargo tauri dev` 自动重编重启。
- 改服务（`server-rs`）：编译后要重新装配，或直接 `dev.ps1 -Stage`（脚本会先重编服务再 stage）。
- 改前端：重跑 `classbeat-tools stage`（或 `dev.ps1 -Stage`）后重启。
- 服务日志：`%TEMP%\classbeat-dev-data\logs\app.log` + `server.log`。

## 5.6 CI（`release.yml` 里的 `desktop` job）

Tauri 的 Windows 产物**必须**在 Windows runner 上构建。0.5.1 起 `release.yml` 里加了
`desktop` job（当时还与打 zip 的 `package` job 并行、往同一个 Release 挂文件）；
**0.5.3 起 `package` job 随老形态退役，只剩这一个 job**，它自己创建 Release。

它做的事，顺序不能换：

1. `dtolnay/rust-toolchain@stable` + `swatinem/rust-cache@v2`（三个 workspace 都缓存）
2. **检查签名密钥**：`TAURI_SIGNING_PRIVATE_KEY` 为空就 `::error::` 直接失败——宁可不发版，
   也不要发一个"老用户更新必失败"的包
3. 编 `server-rs` 与 `tools-rs`（`stage` 要拷 `classbeat-server.exe`）
4. `classbeat-tools stage --data sample`
5. `npm ci`（`desktop/` 下，`tauri-cli` 从 devDependencies 拿，版本锁死）
6. `npx tauri build`，带两个签名环境变量 → 出 `-setup.exe` / `.msi` 与各自的 `.sig`
7. `classbeat-tools make-latest` → `desktop/dist/desktop/latest.json`（`--base-url` 指到本次
   Release 的 `download/<tag>`；说明用 `--notes-file CHANGELOG.md`，工具取第一节、去掉
   Markdown 记号、按「；」连成一句话——面板是 `textContent` 渲染，塞原文会显示成
   `## 0.5.2 — 日期 - 条目 - 条目`）
8. `classbeat-tools single --data sample` → `classbeat-<ver>-single.html`（单文件演示版，
   以前这段在 `tools/package.py` 里）
9. `upload-artifact`（保留 30 天，出问题可以先从 artifact 捞包）
10. `gh release create` 把 **setup.exe + .exe.sig + latest.json + single.html** 一起挂上去
    （只有一个 job 了，不需要再轮询等 Release）

仓库需要两个 secret：`TAURI_SIGNING_PRIVATE_KEY`（minisign 私钥全文）、
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。公钥在 `tauri.conf.json` 的 `plugins.updater.pubkey`；
**换钥匙等于让所有老版本验签失败**，务必沿用同一对。

本地没有 `cargo-tauri` 时脚本会退回 `npx --yes @tauri-apps/cli@^2 build`（需要联网装一次）。

**排错：`desktop` job 二十几秒就红**。那基本只有一种原因——仓库没配签名 secret，
第 2 步的守卫直接 `::error::` 退出（Rust 还没开始编，所以特别快）。0.5.1 打 tag 那次就是这样：
Release 建出来了，但 `latest.json` 缺失，老用户仍升不上来。
处理顺序：先补 secret，再在 Actions 页面点 **Re-run failed jobs**（不用重新打 tag）。

一时补不上 secret、又急着让老用户能升级，可以手工补挂三个文件（0.5.1 用过这条兜底）：

```bash
gh release upload v0.5.1 \
  desktop/src-tauri/target/release/bundle/nsis/ClassBeat_0.5.1_x64-setup.exe \
  desktop/src-tauri/target/release/bundle/nsis/ClassBeat_0.5.1_x64-setup.exe.sig \
  desktop/dist/github/latest.json --clobber
```

挂完必须验两件事：`releases/latest/download/latest.json` 返回 200 且 `version` 是新的；
线上包的 sha256 与本地包一致（`curl -sL <url> | sha256sum`）。
## 5.7 更新链路

```
打 tag → CI 构建 → 生成 classbeat_<ver>_x64-setup.exe + .sig（minisign）+ latest.json
→ 上传到更新源（现有加速域名 + GitHub Releases 双源）
→ 客户端 tauri-plugin-updater 拉 latest.json → 验签 → 下载到 %APPDATA%\ClassBeat\backups\installers\
→ NSIS 被动安装（有进度条、无需点击）→ 应用重启 → 首启健康检查
→ 失败则用 backups/installers 里的上一版回滚
```

`tauri.conf.json` 的 `plugins.updater.endpoints` 现在只剩一条：GitHub 的
`releases/latest/download/latest.json`（**必须可用**，它就是老用户的升级入口）。
2026-11-23 删掉了原来的第二条 `classbeat.example.com` 占位加速域名——它没有任何接上真源
的计划，却让每次检查更新多等一次超时。将来真有校内加速源，加回来是一行 JSON 的事。
`pubkey` 是真实 minisign 公钥，**换钥匙等于让所有老版本验签失败**。

**老用户能不能自动升上来，只看一件事**：`releases/latest/download/latest.json` 能不能取到。
`tauri-plugin-updater` 认的就是这个固定路径，Release 里只有 `-setup.exe` 而没有 `latest.json`
（或只有旧 tag 上有），客户端点"检查更新"必然报"无法获取更新信息"，只能手动下载重装。
0.4.x 到 0.5.0 之间所有老用户都卡在这，0.5.1 的 `desktop` job 才算把这条路接通。

`latest.json` 用工具生成，不再手写（手写最容易漏的是 `pub_date` 格式和下载 URL）：

```powershell
classbeat-tools make-latest `
  --bundle desktop\src-tauri\target\release\bundle\nsis `
  --version 0.5.1 `
  --base-url https://github.com/sulengyin/ClassBeat/releases/download/v0.5.1 `
  --out dist\github\latest.json `
  --notes "0.5.1：补上 latest.json，老版本可以自动升级；右下角改悬浮菜单；默认全屏；图标重绘。"
```

它会挑 `.nsis.zip` 优先于 `-setup.exe`、按 `_{version}_` 过滤、**缺 `.sig` 直接失败**，
并把签名原文写进 `platforms.windows-x86_64.signature`。几个源就换 `--base-url` 与 `--out` 各跑一次
（现行四个：GitHub、加速域名，两个本地测试源；公网那两个的包 URL 必须与 Release 里实际附件名逐字一致）。

0.5.0 / 0.5.1 出包后都按这套流程验过：源里读回的 `version`、`signature` 与 `.sig` 一致，
下载到的包 sha256 与本地包一致（记录见 [`12`](12-服务从Python迁到Rust.md) §12.9）。

## 5.8 发布检查单

- [ ] `classbeat-tools verify` 全绿（0 条 remind / 0 条 FAIL）
- [ ] `classbeat-tools stage` 后 `resources` 里 `.py` 数量为 0、无 `resources/python`、有 `classbeat-server.exe`
- [ ] `resources/build-info.json` 的 `version` == `tauri.conf.json` 的 `version`（verify 会拦）
- [ ] **先 commit 再出包**，否则 `build-info.json` 的 `build` 号指向前一个提交
- [ ] `cargo tauri build` 一次通过（本仓库首次构建需要联网拉 crates）
- [ ] `pubkey` 已替换，`createUpdaterArtifacts: true`
- [ ] `classbeat-tools make-latest` 生成各源 `latest.json`，signature 与 `.sig` 一致
- [ ] `classbeat-tools single` 出的单文件能双击打开（数据是 sample 的化名班级）
- [ ] Release 里 `latest.json` 能从 `releases/latest/download/latest.json` 取到（这是老用户升级的唯一入口）
- [ ] exe / setup / msi 均已 Authenticode 签名（带时间戳）
- [ ] Defender + 360 + 火绒 三扫无误报
- [ ] 验收 A/B/C 在一台干净 Win10 与一台教室机上各跑一遍
