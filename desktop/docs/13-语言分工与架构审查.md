# 13 · 语言分工与架构审查（2026-11-22）

0.5.0 把服务迁到 Rust、0.5.1 补上更新链路之后，"哪个组件该用什么语言"就没人再统一说过
一遍。结果是有三套东西并行：老 Python 形态（zip + pythonw + 看门狗）、Rust 桌面形态、
以及两边都要维护的 JS 前端。这份文档把判定标准写死，逐组件过一遍，并记下这次审查的
发现与处置。

---

## 13.1 判定标准：三条

**① 跑在谁的机器上、失败谁承担。**
跟着安装包发到老师电脑上的东西，必须是"解压即可运行、不依赖外部运行时、体积可控"的：
Rust（静态链接、单 exe）或前端 JS（浏览器自带运行时）。
只在开发机/CI 上跑一次的东西，语言随意，优先用现成轮子——为一次性任务引一整套工具链是亏的。

**② 它是产品，还是尺子。**
产品（老师看得见的行为）**只留一份实现**。
尺子（参考实现、冻结基准、交叉校验）**允许第二种语言**，但必须满足两条：输出被冻住、
每次改动都被测试比对。这样两份实现一旦漂移就报错，而不是悄悄各走各的。

**③ 入口越少越好。**
同一件事有两个入口，就一定有人从错的那个进去。打包、更新、验收都是这样：
老形态和桌面版各有一套更新器、各有一套打包链，维护成本不是加法而是乘法。

## 13.3 发现一：`data.js` 有两份生成器（已加护栏）

`tools-rs/src/bundle.rs` 和 `tools/bundle.py` 做的是同一件事：把 `sample/`（或 `data/`）
的七个 JSON 拼成 `window.RHYTHM_DATA`。这份重复是有原因的——
JS 单元测试与 e2e 的 CI job 里没有 Rust 工具链，而 `stage` 装配必须用 Rust 版。

如果哪天两边漂了，症状是**测试跑的和发出去的不是同一份配置**，极难发现。所以：

- 两边输出实测逐字节一致（只有首行注释与 `generatedAt` 不同，我核对过）；
- 约定：`generatedAt` 之外必须相同，改动任何一边都要同步另一边；
- 待办（未做）：在 `release.yml` 的 desktop job 里加一步"两份输出比对"，
  把它从"我核过"变成"CI 卡住"。这一版先记在这里，避免没验证就写进流水线。

## 13.4 发现二：图标只能用这台机器重生成

`tools/make_icons.py` + `make_ico.py` 是纯 Python、零第三方依赖（自己写的 PNG 编码），
这点很好——`--help` 里写的"CI 可跑"是真的。问题在别处：

- 它**不进任何构建链**，产物（`desktop/src-tauri/icons/classbeat.ico`、
  `server/icons/*.png`）是入库的静态文件，只有换品牌图时才跑一次；
- 所以它不是"产品实现"，而是"素材工具"。这类工具留在 Python 里不算"强行 Rust"，
  真要迁，收益是省掉一次 `python3`，成本是 400 行位图代码从零搬。

本次只做了一件事：`make_ico.py` 的输出路径从 `tools/launcher/classbeat.ico`
（老形态的快捷方式图标，已删）改到 `desktop/src-tauri/icons/classbeat.ico`，
源图从 `tools/launcher/logo-source.png` 挪到 `tools/assets/logo-source.png`。

## 13.5 发现三：老形态其实是第二套产品（已退役）

退役前它是这样一套东西：

| 部分 | 行数 | 只在老形态里存在 |
|---|---|---|
| `server/*.py`（服务 + 守护 + 页面内更新器 + 清单） | 2,752 | 是 |
| `tools/package.py`（zip / 单文件 / 免安装 Python / .bat 生成） | 708 | 是 |
| `tools/build_installer.py` + `tools/installer/`（7zSD 自解压） | 310 | 是 |
| `tools/make_update.py`（老 `update.json` 清单） | 214 | 是 |
| `tools/launcher/*.ps1` + `.cmd`（kiosk / 看门狗 / 自启 / 逃生门） | 1,504 | 是 |
| `tools/smoke_windows.py` + `test_server` / `test_package` / `test_updater` / `test_update_manifest` | 1,810 | 是 |
| `desktop/scripts/*.py`（0.4 迁移期的等价性证据脚本） | 1,130 | 是 |
| 合计（含 `update.json`、`equivalence_probe.cjs`、旧 ico） | **约 8,700 行 / 29 个文件** | |

代价不只是行数：

1. **两套更新器**。桌面版走 `tauri-plugin-updater` + minisign；老形态走"页面里点检查更新 →
   服务下载 zip → 白名单替换 → 健康检查 → 回滚"。两套互不认识对方产物，0.3.x 的"跨代自愈"
   就是在这上面打仗。
2. **CI 每次都下载 11 MB 免安装 Python**，还要 `pip install py7zr` 打自解压包。
3. **自解压 exe 是杀毒误报的常客**——而这个 11 MB 的 exe 只为了让老师省一次"安装"。
4. 改一条作息规则，要在 Python 与 JS 两边同步；改一个卡片样式，要跑三条测试链。

处置（本次已执行）：

- 删除上表全部文件，`release.yml` 的 `package` job 与 `smoke.yml` 的 `windows-smoke` job 一并去掉；
- 「不装软件也能看」这个需求**没有丢**：单文件演示版改由 `classbeat-tools single` 出
  （Rust，复用同一份数据打包逻辑），打标签时和安装包一起挂到 Release；
- 「服务」的回归不再靠 Python 测试：桌面侧的 `verify`（装配不变量）+ `accept`（运行期 17 项）
  接过来，e2e 也从"起 Python 服务"改成起 `classbeat-server.exe`——测的就是发出去的那个二进制。

副作用（如实记录）：`test_server.py` 里那 696 行针对 Python 服务端点的断言（消息长度、
撤回窗口、端口顺延、路径穿越）**没有等价物**。其中一部分由 `accept` 与 e2e 覆盖，
但"用 30 种畸形请求试端点"这类用例确实没了。这是退役必然的损失，记在这里而不是假装没有。

## 13.6 发现四：核查"有没有强行用 Rust 的地方"

逐条看过，**没有**发现"该用脚本却硬写成 Rust"的组件。三个容易被怀疑的地方：

| 位置 | 看起来像"强行 Rust"？ | 结论 |
|---|---|---|
| `tools-rs/src/accept.rs`（566 行）用 Win32 枚举窗口、量窗口尺寸、杀进程 | 像。这些用 PowerShell 十行就能写 | 但它验的正是"壳在真机上的行为"：全屏、误关后自愈、单实例、托盘退出。用 PowerShell 写等于"用被测对象的同族工具验它"，而且 `accept` 要在一台干净机器上跑，不该假设有 PowerShell 环境。留在 Rust |
| `server-rs/src/pyjson.rs`（223 行）复刻 Python `json.dumps` 的格式 | 像。Python 都退役了还留着它干嘛 | 它的另一半职责是**确定性序列化**：备份包按"排序 + 紧凑分隔符"算哈希做去重，格式一变老备份就对不上。所以不能直接换 `serde_json`。**待办**：把模块文档从"复刻 Python"改成"稳定的确定性序列化（历史格式与 Python 版一致）"，并注明哪些调用点是承重的 |
| `tools-rs/src/stage.rs` 装配资源、写 `build-info.json` | 这些事 `xcopy` + 一个 ps1 也能干 | 它同时承担"装配不变量"（不许有 `.py`、版本双轨必须一致、资源齐全），和 `verify` 是同一套断言的两端。分开写必然漂 |

反过来，"该用 Rust 却还用脚本"的地方，本次清完了：单文件打包已从 `tools/package.py` 搬到
`classbeat-tools single`；桌面构建链（`build_windows.ps1`）只做编排，不再写业务逻辑。

## 13.7 发现五：更新面板的两处说法不一致（已修）

`/api/update/apply` 返回 409 时说的是"桌面版由 **ClassBeat 应用**统一更新"，
而 `/api/update/status` 的 `blockedReason` 写的是"桌面版由**程序自己**更新"。
同一个面板，两句话。0.5.1 改文案时只改了一处。

现在合并成一个常量 `DESKTOP_UPDATE_HINT`，两个端点都引用它。

## 13.8 发现六：更新说明把 Markdown 原样塞进面板（已修）

`release.yml` 里是 `--notes "$(head -30 CHANGELOG.md)"`。大屏的更新面板用
`textContent` 渲染，换行会塌成一段，于是老师看到的是：

```
# 更新记录 老师能直接感知到的变化写在这里；内部重构不列。 ## 0.3.27 — 2026-11-22 - **右下角菜单里…
```

改成 `--notes-file CHANGELOG.md`：工具取第一节、去掉 `**` `` ` `` 与链接记号、
条目用「；」连起来、超长在最近的「；」处截断，再以安装包版本作前缀。
产出变成一句话：`0.5.2：右下角菜单里「深色」前面有空缺：…`。

线上那份也已经换掉（只换 `notes`，签名与 URL 沿用 Release 上的原件，否则与线上包对不上）。

## 13.9 发现七：更新源里有一个必然失败的地址（未改，留待决定）

`tauri.conf.json` 的 `plugins.updater.endpoints` 第二项是
`https://classbeat.example.com/update/latest.json`——占位域名，永远连不上。
第一个源（GitHub）通的时候它不会被用到；GitHub 被墙时它会白等一次超时。

要么接一个真实的加速源，要么删掉这一项。**没在这次改**：改它要重新打包发版才生效，
而这次不发版。删掉是安全的（更新器本来就只在第一项失败后才看它）。

## 13.9b 发现八：跨零点的消息会被大屏藏起来（已修，CI 抓到的）

把 e2e 的被测服务换成 Rust 之后第一次跑 CI，有 6 条红：都是"手机发一条，屏上应该
出现"。原因不在 Rust 服务，而在页面：

- 消息的到期时间只存到分钟。`23:55` 发 10 分钟 → `until = "00:05"`；
- 页面 `visible()` 用 `nowHM() >= msg.until` 比字符串，`"23:55" >= "00:05"` 为真，
  于是当场判成"已过期"，屏上什么都不显示；
- 服务端 `messages.rs::expired()` 早就对 `00:00–06:00` 做了例外，所以服务认为消息
  还活着、页面却藏起来——两边打架，且只在 23:50–24:00 这十分钟里发作。

本地跑了十几轮都没撞见，是因为每次都在零点之后（`00:01` 发起，`until` 是 `00:11`，
字符串比较恰好成立）。已把判定抽成 `Remote._noticeExpired(until, now)`，与服务端
同规则，并在 `test_dom.js` 里加了 6 条断言（跨零点前/后、同日过点、未到点、无 until）。

## 13.12 遗留与建议（按优先级）

**P1 · 该做**
1. `data.js` 双实现的 CI 比对（13.3）——现在只有人工核对。
2. `pyjson` 的文档改口（13.6）——别让下一个人以为它只是迁就 Python 的临时补丁。
3. 更新源第二项：接真源或删（13.9）。

**P2 · 想清楚再做**
4. `server/` 改名（现在只剩手机页静态资源，名字误导）。牵动服务的静态根、装配清单、e2e。
5. Python 服务端点的"畸形请求"用例有没有必要用 Rust 重写一批（13.5 结尾）。
6. `test_dom.js`（2,020 行，含手写 DOM 桩）以后不再往里加断言，新东西优先写 e2e；
   它是"第二套 DOM 实现"，长期是负担。

**P3 · 已接受的风险**
7. Authenticode 代码签名仍未做，首次安装会有"未知发布者"提示。
8. GUI 上"点检查更新 → 被动安装 → 重启"这一串，还没有在装着旧版的机器上真跑过一次
   （这台机器装的始终是最新版）。
